## The route's order of checks (each refusal a fixed code, nothing proposed before the last)
1. same site: `Origin` equals the request's origin and `Sec-Fetch-Site` is `same-origin` (else 403 `forbidden`)
2. lane id shape (404 `not_found`)
3. session, lane membership, role with `own_mail`, AAL2 (401 `no_session` / 403 `mfa_required` / 404)
4. step-up within the LANE's Teams window (`teamsStepUpWindow`, never from the request) with the Teams bound (403 `step_up_required`)
5. `messages` module visible (404)
6. body read, at most 100,000 bytes, exactly `{conn, chat, text, textSha256, clientRequestId}` (400 `bad_request`)
7. `conn` is a lower-case uuid (400) and one of the caller's OWN Teams rows in this lane (read under RLS, `mine`); another person's, another lane's, disconnected, pending and unknown ids are the SAME 404; the caller's own expired one is 409 `reconnect`
8. 1 request per second per connection (429 `rate_limited`, `retry-after`)
9. chat key decodes (400)
10. approvals entry: write role (403), the connection is the caller's usable Teams connection (404), gates in this order: `lane_off`, `reconnect`, `policy_off`, `drafts_off`, `not_live` (409 `gate_<name>`), text by the Zod schema (400 `invalid_message`), hash (400 `text_mismatch`)
11. propose + approve the computed hash + claim + ONE POST + read-back, inline. Answer `{ok, state}` with `sent` / `checking` / `not_sent` (+ fixed `code`, `message`) / `unknown`; an unclassified failure after step 10 started is 502 `unknown_outcome`.
`cache-control: no-store` on every answer. The database re-checks owner, role, AAL2, the step-up age (`act.approve`), every gate and the single claim.

## What is stored, where, and for how long
- Server: the proposal row holds `payload.text` only while the action is proposed / approved / executing (T-286: emptied by the database in the same statement as every terminal state). Ids, type and hash go to status history and the audit; the text never does. Nothing else stores it: not logs, errors, Inngest events, the approvals history, `result`, claims.
- The one POST body holds the text (to Microsoft).
- Browser: the textarea state; a copy in sessionStorage under `nichols:teams-draft:<lane>:<user>:<conn>:<chat>` for 2 hours (written 500 ms after the last keystroke; removed on Sent, Sent-checking and Outcome-unknown; removed at sign-out by `clearAllDrafts`; per tab, never sent to the server except in the send request). The sent bubble is memory only.
- Logs: the route logs the error CLASS only (`[api/teams-messages] unavailable / send ended unknown`).
