# T-031: Connections and sync runs tables

## Changes
- Migration `20261102042312_connections_and_sync_runs.sql`:
  - `core.connections`: lane, provider (real providers only, no `mock`), external account id (trimmed, secret-scanned), status (`pending` → `active`/`degraded`/`reconnect_required`/`disconnected`), features, features_checked_at, token_expires_at (credential expiry, not access token), last_sync_at (last successful sync), last_error, created_by. Unique per (lane, provider, account); `(id, lane_id)` unique as the target of lane-consistent FKs. No token columns.
  - Lane, provider and account are immutable (trigger); a disconnected row has no token expiry (check).
  - `core.sync_runs`: per-run kind, trigger, status, timestamps, counts, redacted error, Inngest run id; FK `(connection_id, lane_id)` so a run cannot point at another lane's connection; status/finished_at/error consistency checks. Connections with runs cannot be deleted.
  - `core.is_connector_error(jsonb)`: value-for-value match of the strict `ConnectorErrorInfoSchema` (all eight keys, enums, bounds, endpoint as a path template) plus the secret scan. `core.is_connection_features(jsonb)`: snake_case keys to booleans, no credential names.
  - RLS: standard lane policy, `connections` view on connections and `health` on sync runs (owner, admin_technical). Column-level grants: `created_by` is not readable; any new column is hidden until granted.
- `packages/connectors/src/contract/schemas.ts`: doc comment on `token_expires_at`.
- `packages/core/src/db/types.ts` regenerated (also picks up `mfa_enrolment_state` from T-019, which had not been regenerated).
