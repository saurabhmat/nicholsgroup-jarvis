# T-061: comms and calendar index tables

## Summary
New schemas `comms` and `cal` with `comms.message_index` (metadata, priority and classification fields, optional summary that requires an approval marker) and `cal.event_index` (event metadata). No body, snippet, preview or description column. Standard lane RLS ('comms' and 'calendar' views, AAL2), service_role-only writes, same-lane Google/Microsoft connection via composite FK, idempotent unique keys. Retention purge functions: `comms.message_index_purge` (default lane policy `retention_days`: PKG 90, NL 30) and `cal.event_index_purge` (default 180 days, floor 30), both service_role only, for T-042.
