## Summary
The brain setup interview now runs inside the assistant chat ("Set up my brain" / "Set up my Personal Assistant" chips, or typing the same), with Settings → AI brain as the fallback (same component, same checks). Up to three questions per step, "Already set: … (Edit)" for known answers, skip rules from the bank, a diff card and a Save button per group, a summary with per-section Edit (reconfigure by section), Confirm, the test-briefing check and Activate.

- Question bank is data (`docs/specs/brain-interview.md` → `packages/modules/brain/src/interview/bank.ts`): A1–A10, B1–B15, 10 groups of at most 3 questions. A unit test checks every `config.*` target is a path of `employeeConfigSchema`.
- Preview (`propose`) is read-only. `save` re-plans from the pages as stored now and refuses (409) unless the result is byte-identical to the proposal the user saw (`proposalId` = SHA-256 of lane, path, base version and new text). Writes go only through `store.saveDocument` / `store.saveEmployee` (core.brain_* wrappers over the session-bound lane client). No service role, no model call, no external write.
- Part A saves pages (About-Me and Preferences in the home lane, Work in the current lane). Part B saves the draft employee (prose + normalised config) per group; Confirm re-validates with `loadEmployeeConfig` (fail closed) and shows effective permissions per lane; Activate re-validates and sets `active`.
- A missing mailbox or an unconnected one shows a link to Settings → Connections (`/<lane>/settings#connections`). There is no connect action in the interview (tested: no connect button).
- Answers are screened before planning: credentials, SSN/card/bank numbers (store rules) and Nichols Law content (refused with a reason, nothing saved).
- Owner-only: the route needs `requireRole(owner)` at AAL2 and the brain view in the lane; the entry points are hidden otherwise.

## Scope decisions (delegated by Saurabh, Nov 8)
1. No model in the interview: deterministic engine; edits are section replacements built from the user's typed answers. (The acceptance said "model's interview output is a proposal"; nothing a model produces can reach a save, which is the stronger guarantee. A model polish step can be added later behind the same diff card.)
2. Test briefing: `TEST_BRIEFING_AVAILABLE = false` shows "Your test briefing arrives with the daily briefing (T-213)." with a disabled button; activation does not wait for it (per the backlog note).
3. Part B per-group Save writes the draft employee row; Confirm is a validation step, not a second write.
4. B13 skip rule accepts `email_draft` or `email_send` (D-34).
5. A5/A6 per company for the lane the page is open in. B14 is a short voice description, not pasted replies (rule 6). B12 uses the canonical section order.
6. "Part B done" = the employee row exists (no SQL for a per-group marker).
7. Typed requests like "set up my brain" start the interview instead of going to the model (client-side match, ≤80 characters).
8. When the chat itself is unavailable (no AI config or no readable categories) the assistant page still offers the interview to an owner, since it needs no model.
