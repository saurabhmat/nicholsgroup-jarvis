# T-011: Lane config (per-lane source settings, no secrets)

Approved by Saurabh, Oct 31, 2026 (combined branch `agent/pilot-build`; split into its own PR later).

## Changes
- Migration `20261031043550_lane_config.sql`:
  - `core.lane_config (lane_id, version, config jsonb, created_at, created_by)`: one row per version, primary key `(lane_id, version)`. A trigger makes it insert-only (update, delete and truncate raise 42501) and gapless (the next version must be max + 1, serialised per lane by an advisory lock; a gap raises P0001). `created_by` references `core.users` with `on delete restrict`.
  - `core.jsonb_has_secret(jsonb)` in a CHECK: rejects credential-named keys (token, secret, password, api key, private key, credential, bearer, signing key, cookie, session id, auth, authorization, pat; as whole words between `_`/`-`, so `max_tokens` passes) and secret-looking string values at any depth (the vendor prefixes from `secret-patterns.js`, PEM private keys, any JWT, URLs with a password), after stripping all surrounding whitespace including NBSP, zero-width and BOM. The config must be a JSON object under 64 KB.
  - `core.lane_config_public(lane)`: security definer; the non-sensitive subset of the current config (modules, KPIs, finance settings, metrics, controls, tie-out, freshness, Stripe livemode, `approvals_live`, assistant limits) for any member of the lane at AAL2.
  - `core.lane_config_current` (security_invoker view): the highest version per lane.
  - RLS: select at AAL2 with the `config` view (owner, admin_technical). Writes: service_role only, insert only.
- `@nichols/core/lane-config` (`packages/core/src/lane-config/`): strict Zod schema (unknown keys rejected at every level) with the spec defaults:
  - modules and KPI ids (finance §4.1)
  - QBO realm and mapping mode, Stripe account and livemode, GHL location and paid-subscriber rule (null until D-3)
  - entity mapping per entity code (QBO class and customer ids, Stripe products, GHL tags and products) and bank accounts with their owning entity (D-17, D-18)
  - mailboxes and priority senders; briefing time
  - finance (accounting method, weekly cash time, monthly close trigger); `metrics.start_month`
  - controls thresholds, tie-out tolerance, freshness
  - approvals (`approvals_live` false, approver roles = owner only, step-up age ≤ 900 s, expiry per action type, retention, allowed mailboxes, monday column allowlist)
  - assistant rate limits and `max_snippet_chars` (300)

  GoHighLevel tags are free text (spaces allowed, no control characters). `parseLaneConfig()` runs the env secret-value scan first (depth-capped) and reports paths only, never values.

- Seed: `lane-config` section (re-runnable: `where not exists`): version 1 for every lane; PKG gets a synthetic config (fake realm `1001`, `acct_synthetic0001`, synthetic class, product and tag ids, `example.test` mailboxes); the other lanes get `{}`.
- Tests: `040_lane_config.test.sql` (45 pgTAP), `lane-config.test.ts` (10, including the seed config passing the Zod schema).

## Decisions
- Shape validation lives in Zod (the write path); the database enforces only "object, no secrets, insert-only, gapless". Keeping the full schema out of SQL avoids two diverging copies.
- Readers: the full config (mailboxes, priority senders, account ids, entity mapping) needs the `config` view (owner, admin_technical). Every member reads the non-sensitive subset through `core.lane_config_public()`.

## Review (security, Oct 31, 2026; no BLOCKER or HIGH)
- M1 (fixed): the database check stripped only spaces; tab-, newline- or NBSP-padded secrets passed. Now all whitespace is stripped (tests); key names tightened (hyphens, auth, authorization, pat) without flagging `max_tokens`.
- M2 (fixed): `approver_roles` accepted any role; now owner only (approvals spec §8 test 4), step-up capped at 900 s.
- M3 (fixed): roles without the `config` view could not read KPIs, thresholds or `approvals_live`; added `core.lane_config_public()` (tests: finance_operator reads it, mailboxes omitted, non-member and AAL1 get null).
- M4 (fixed): `created_by on delete set null` collided with the insert-only trigger; now `restrict` (test).
- M5 (fixed in part): GHL tags are free text. Accepted limitation: a value that starts with a vendor key prefix (e.g. a tag `re_engaged`) is refused by both checks; rename the tag. Failing closed is preferred over a narrower Resend pattern in the shared env scan.
- L1 `max_snippet_chars` added; L2 version-gap errors use P0001 and the tests match the message; L3 cross-lane test with APK enabled; L4 seed re-runnable; L6 64 KB cap and a depth cap in the scanner; L7 `account_id` max 64; L8 `jsonb_has_secret` not executable by authenticated. Open: L5 (`created_by` set by the writer from the verified session; enforced when the config editor and the audit log, T-014, land). Opaque secrets (random hex/base64) cannot be detected by pattern; the strict schema and short id fields limit where one could go.
