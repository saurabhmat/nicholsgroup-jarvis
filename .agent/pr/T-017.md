# T-017: Session → allowed lanes helpers

## Changes
- `@nichols/core/auth` (`packages/core/src/auth/index.ts`, server-only, in the auth-session path T-003 reserved):
  - `cookieSessionReader(cookies)`: reads the Supabase session from the request cookies with `@supabase/ssr` and verifies the access token with `auth.getClaims()`; the user id and AAL come from the verified claims.
  - `createGuards(reader)`: `requireSession()` (AAL2 required; `{ allowAal1: true }` only for sign-in/MFA pages), `requireLane(laneId)` (session + lane client from the router), `requireRole(laneId, roles)` (requireLane + `core.has_lane_role`). Failures: `AuthError` 401 `no_session`, 403 `mfa_required` / `forbidden`; an unreadable session counts as none; lane refusals map to 403, other errors propagate.
  - `authErrorResponse(e)`: no-store JSON `{ error: reason }`.
- `apps/web/lib/guards.ts` (request-scoped guards from `next/headers` cookies) and the sample protected route `GET /api/lanes/[laneId]` (200 `{lane}` for an AAL2 member of an enabled lane, 401/403 otherwise, 503 on other errors).
- Dependency: `@supabase/ssr` 0.12.7 (pinned) in `@nichols/core`.

## Tests
- `auth.test.ts` (11): server-only; AAL2 session returned; no session or a failing reader → 401; AAL1 → 403 unless allowed; requireLane passes the session to the router, maps LaneAccessError to 403, never calls the router at AAL1 or without a session, propagates other errors; requireRole calls `has_lane_role` with the session user and refuses false/error/non-boolean/empty roles; error response shape.
- `pnpm --filter @nichols/web typecheck` and lint pass.

## Review (security, Oct 31, 2026; no BLOCKER or HIGH)
- M1 (fixed): `cookie-reader.test.ts` (6) pins the verification: the session's own access token is verified, user id and AAL come from its claims (not the cookie's user object), invalid/forged/expired tokens and subject-less claims are no session, an auth outage throws.
- M2 (fixed locally, human for production): `jwt_expiry = 900`; production setting and asymmetric signing keys are H-026; approval/step-up paths will use `auth.getUser()`.
- L3 (fixed): outages and configuration errors propagate (the route answers 503 and logs the error class only) instead of posing as "sign in required".
