# T-033: Token access, SecretValue, redacting logger

## Changes
- `packages/connectors/src/vault/secret.ts`: `SecretValue`. JSON, string conversion, template literals and `inspect` all print `[redacted]`; the plain value comes out only through `reveal()` (restricted name: packages/connectors only). Every value, plus its URL-encoded, base64, hex and JSON-escaped forms, is registered in a private, bounded registry that the redactor scrubs by exact match. `reveal()` re-registers the value so a credential in use is not evicted.
- `vault/tokens.ts`: `getToken` / `storeToken` / `rotateToken` / `revokeToken` over the T-032 functions. Each call is keyed by (lane, lane-bound connection); secrets go only as RPC bind parameters; database messages are replaced by fixed text.
- `vault/loader.ts`: the real `ConnectionLoader`. Reads `core.connections` by (lane_id, id) with the lane's job client and mints the row lane-bound. A missing row and an other-lane row both give `not_found`; a lane without a job client gives `connection_unavailable`.
- `log/`: the shared connector logger (one JSON line per entry) and the redactor. Free text is redacted by exact match on known secrets, then by shape: Authorization and API-key headers, credential query parameters, JSON and key-value fields, JWTs/JWEs and vendor key prefixes. Fields are redacted with a log-specific key policy: credential, financial and content keys are dropped, but `ConnectorError` detail, provider codes and expiries are kept. Input is capped at 64 KB.
- `contract/errors.ts`: `ConnectorError` redacts its message. Provider codes and transaction ids get an exact-match plus whole-value check (no shape patterns, so codes like `secret_key_required` stay readable). The endpoint is redacted, and set to null unless it is a plain path.
- `@nichols/connectors/redact`: `redactText`, `redactFields` and `REDACTED` only, for Sentry (T-041).
- Lint (`packages/eslint-plugin`):
  - `no-vault-access`: the Vault schema, Vault objects and functions (including in SQL text) and the token functions may be named only in the token vault.
  - New `no-cross-package-relative`: a relative import cannot reach into another package's sources.
  - New restricted names: the token functions, `reveal`, `createTokenVault`, the registry functions (`rememberSecret`, `scrubKnownSecrets`, `forgetSecretsForTests`), `mintLaneBoundConnection`, `buildProviderSchemas`, `connectionLoader` and `createConnectionLoader`.

## Tests
- `canary.test.ts`: a synthetic token never appears in JSON, string or inspect output, structured clone, logs (nested fields, errors, child loggers), `ConnectorError` message, ids or endpoint, in any of its encoded forms. New shapes are redacted; false-positive cases are kept readable; the logger keeps `ConnectorError` detail.
- `tokens.test.ts`: lane guard, RPC arguments, error mapping, loader columns and filters, `not_found` / `invalid_input` / `transient` / `connection_unavailable`.
- `boundary.test.ts`: the vault and logger are not exported from the root or any subpath; the redact subpath offers only the three names.
- `config.test.js`: fixtures for every new restriction, inside and outside the allowed paths, including relative-path bypasses from apps/web and modules, and Vault SQL text.

## Risks
- Exact-match scrubbing needs values of 8 characters or more, and only covers credentials this process has seen; the shape patterns cover the rest on a best-effort basis.
- The RSC and prompt-builder canaries are approximations (JSON and structured clone, template literals), not a real React Flight render or prompt builder.
- Server code can still reach `vault.*` directly. Lint is the control (§7, Nov 2).
