# T-227: Explicit per-section completion for the setup interview

## Migration: YES
`supabase/core/supabase/migrations/20261109090000_brain_section_completion.sql` (one new table, one definer writer, two invoker wrappers). Local only (`pnpm test:db`); nothing was applied to a linked or remote project. Production needs it run by hand after part 6 (a `part-7-T-227.sql` was generated in the ignored `bootstrap/manual-migrations/` folder, same format as part 6, with guards); the app degrades safely without it (completion reads fail, so nothing shows as done; Save would fail on the completion call, so apply the migration before deploying this code).

## Summary
T-226's derived rule could not tell a kept default from "never answered". Completion is now stored.
- **Table `brain.section_completions`** (`lane_id`, `user_id`, `section_id`, `completed_at timestamptz`, primary key on all three; `lane_id` not null, FK to `core.lanes`; `section_id` checked by `brain.valid_section`, which lists the bank's ten ids; a unit test keeps the SQL list equal to the bank). RLS: AAL2 + the lane in `allowed_lanes(uid, 'brain')` + own rows (custom policy, on the catalog's `custom_policy_ok` list). No user DML; no service_role access.
- **Writer `brain.section_complete(lane, sections[])`** (security definer, on the catalog's reviewed list): AAL2, owner role in the lane, rows addressed by `auth.uid()`, 1 to 20 known section ids else `22023`, idempotent (first `completed_at` is kept). Wrappers `core.brain_section_completions(lane)` (invoker) and `core.brain_section_complete(lane, sections[])` (invoker).
- **Set when:** the user clicks Save on a section (`saveGroup`, even when every value is a kept default and the plan has no changes: no brain write, completion still recorded); or **Nothing to add** (new `complete` interview action: writes no page or profile, answers stay "Not provided"). Wizard: "Save & continue" is available for an empty diff ("Nothing would change. Saving records this section as done."); "Nothing to add" on every incomplete section; "Continue" on a section with nothing to ask records it. Chat/page flow: Save for an empty diff and a "Nothing to add" button.
- **Single rule:** `loadInterviewState` and `loadProgress` set `GroupView.complete` from the stored rows. The menu badge, rail chips, progress bar, first-incomplete, Home banner, More row, Settings list and the chat/page section badge all read `complete`. `GroupView.done` stays for chat routing only. A completion that cannot be read shows nothing complete.
- **Backfill (mechanism and why):** app-side, lazy, one time. The T-226 derivation lives in the interview engine (TypeScript: bank + page parsing), not derivable in SQL, so a migration cannot do it. On the first state or progress load for a user with NO completion rows in the home lane, the sections the derived rule counts complete are recorded through the same writer. Idempotent (`on conflict do nothing`), never removes anything, and runs only while the user has zero rows (so it cannot resurrect a section later, and it stops after the first Save, Nothing to add or backfill). A failed backfill write shows nothing complete rather than guessing. Tested (server: backfills once; not again; not when rows exist; fail-safe; pgTAP: idempotent first-wins).
- Files: migration, `252_brain_section_completion.test.sql` (37 assertions), catalog test lists, `packages/core/src/db/types.ts` (regenerated), `server/store.ts` (`listCompletions`, `completeSections`), `server/interview.ts` (`withCompletion`, `completeGroup`, Save records), `interview/request.ts` (`complete` action), `jobs/retention.ts` (retention catalog entry), `apps/web/lib/brain-interview.ts` (route), `brain-wizard.tsx`, `brain-interview.tsx`, e2e spec step.

## Risks / notes
- Deploy order: migration first (see above).
- Completion lives in the user's home lane (where the brain is); a user with several lanes has one set of rows.
- "Nothing to add" cannot be undone from the UI (rows are never deleted); Edit and Save still work on a completed section.
- T-226's derived `complete` rule is now used only as the backfill source.
