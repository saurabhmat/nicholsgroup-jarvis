# T-020: Step-up helper

## Changes
- `@nichols/core/auth`: `requireStepUp(maxAgeSeconds)` (30 – 3600): AAL2 plus a TOTP code entered within the window, read from the verified token's `amr` claim (`totpVerifiedAt()`: latest `totp`/`mfa/totp` timestamp; the timestamp-less string form fails closed; a future timestamp beyond 60 s does not count). `AuthError("step_up_required")` (403). `VerifiedSession.mfaVerifiedAt`. `createGuards` takes an injectable clock for tests.
- `/mfa?reauth=1`: an AAL2 user with a factor gets "Confirm it's you" and enters a fresh code (new `amr` timestamp).
- `GET /api/session/step-up?maxAge=…` (default 300): 200 or 403 `step_up_required`; no data. Screens use it before offering sensitive actions; the actions call `requireStepUp()` themselves (approvals, T-119/T-193, with `lane_config.approvals.step_up_max_age_s`).
- e2e helpers remember enrolled secrets per persona for the run (`completeMfa`, `nextTotpWindow`); `step-up.spec.ts`.
