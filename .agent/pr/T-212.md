# T-212 Prompt assembly with brain blocks

## Migration
**No SQL, no migration, no production step.** Existing `core.brain_*` read functions suffice (own-only filtering is done on `is_mine`).

## Summary
- `packages/ai/src/prompts` (`@nichols/ai/prompts`): `assemblePrompt` builds the system prompt in spec §4 order: rules (with brain rules), untrusted-data rule, runtime facts, `<brain_user>`, one `<brain_lane lane>` per lane in scope, `<employee>`. `withUserContext` puts the owner's `<user_preferences>` (employee include/topics) in the first user message, never the system prompt.
- Refusals (fail closed, `PromptError`): block for a lane outside the call scope; About-Me/Preferences for a user other than the subject (D-28); About-Me/Preferences or other kinds as lane pages; bad role key.
- Token cap (default 6000, pessimistic 3 chars/token): fixed pieces cut to a quarter, pages dropped handoffs, then briefs, then context, oldest first; runtime block gets a dropped-page note; paths of dropped pages go to the run log via `onPrompt` (never text). No `mem.items` block (T-155).
- Brain text is NFKC-normalised, invisible characters removed, every `<` escaped, so it cannot close or forge a block.
- `packages/modules/brain/src/server/prompt-context.ts`: `loadBrainPromptContext` (own About-Me/Preferences from the home lane in any lane's call; own Context/project pages of the call's lane only; failures become notes, not errors) and `buildEmployeePrompt` (`loadEmployeeConfig` on every run, fail closed; `effectivePermissionsByLane` per lane; include/topics returned separately).
- `chat.ts` now builds its prompt through the assembly (`chatSystemPrompt` kept as a wrapper); `apps/web/lib/assistant.ts` loads the caller's brain context through the session-bound lane client (`requireLane`) and passes it in.
