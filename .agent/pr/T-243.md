## 1. Cash (book balance) from the current balances of PKG's mapped bank accounts
- **Migration `20261121100000_cash_from_bank_balances.sql`** (production part 22):
  - `fin.accounts.current_balance numeric(18,2)`, nullable (QuickBooks `Account.CurrentBalance`).
  - `core.fin_qbo_normalize` sets it on insert and on update (it is in the "is distinct from" tuple). Based on the part 21 body; only the accounts step changed. The `where p.id is not null` safeupdate predicate and all step markers are kept.
  - `core.home_finance` no longer reads the balance sheet. Cash = sum of `current_balance` of active, not deleted bank accounts that are listed in `entities.bank_accounts` with owner = own entity (D-18). An account under another owner, under more than one owner, or whose entity_code is another entity is flagged `shared`. A bank account in no mapping is counted in `cash_unmapped` and not summed. `cash_as_of` = last books sync (`connections.last_sync_at`).
  - Reasons: `bank_mapping_missing`, `no_own_bank_accounts`, `balance_unreadable` (an own account has no balance yet; the text says a re-process fills it). The balance-sheet reasons are gone.
  - Label stays "book balance"; output column names unchanged. No new table, so no new RLS surface.
- TS: reason texts in `apps/web/lib/home-finance.ts`, generated DB types.
- **Tests:** pgTAP 300 (rewritten cash section: own mapped only, other owner / unmapped / inactive / deleted / non-bank left out, shared flags, as_of = last sync, unreadable balance, no own account, class-filtered balance sheet has no effect, cross-lane and AAL1 denial kept), new 316 (column, stored on insert, rounded, null when absent or not a number, updated on change, identical re-run changes nothing, through `service_role`), 130 updated for the one new money column. 315 (no unfiltered UPDATE/DELETE) passes.

## 3. Date.now() / clock prerender errors on /[laneId] and /[laneId]/settings
- **Reproduction:** a local production build (`next build`, synthetic and local-only env, every variable NAME in `.env.local` pre-set to a dummy so no real value loads) shows **no** clock error before or after the change, and `next start` redirects signed-out requests before any page code runs. The error needs a signed-in session (the e2e helper enrols an authenticator on a seeded persona and would break later e2e runs, so I did not use it). So the root cause below is from Next's own source (`node-environment-extensions/io-utils.js`), not from a reproduced log. Please confirm in the Vercel logs after deploy.
- **Cause found:** with `cacheComponents` and `partialPrefetching: true`, a clock read in a static or runtime render stage (before the request's dynamic data) is reported as a sync-IO error for the route. Two places could do that on these routes:
  - `AppShell` (every page, a client component rendered in the layout) called `pageHeading(active, firstName)`, whose `now = new Date()` default ran on every route even when the page was not Home.
  - The two pages read `new Date()` after only `await params` / `loadLane`, with no explicit dynamic point first.
- **Fix:** `nav.ts` no longer defaults any parameter to the current time; the lane layout reads the time after the lane check and passes it to `Shell` -> `AppShell` (the shell never reads the clock; without it Home's phone title is the neutral heading). `HomePage` and `SettingsPage` call `await connection()` first.
- **Regression:** `apps/web/tests/clock-reads.test.ts` (page modules call `connection()` before any clock read; nav / shell read no clock), a test that `AppShell` constructs no `Date`, and `pnpm --filter @nichols/web build 2>&1 | node scripts/check-build-log.mjs` (`check:build-log`) which fails on clock / prerender errors in a build log.
- Note: the phone header greeting is now fixed at the layout's render (a layout is not re-rendered on client navigation), so a session left open across noon or 17:00 keeps the old greeting on the phone band until a reload. The Home title itself is unchanged.
