# T-034: Connector HTTP client + MSW harness

## Changes
- `packages/connectors/src/http/client.ts`: `createHttpClient`, the only way connectors call providers.
  - Base URL must be https (http only on loopback), with no credentials, query or fragment.
  - Paths are templates; each parameter fills one encoded segment, and `.`, `..`, empty values and dot or empty template segments are refused. A final check confirms the URL parser did not rewrite the path.
  - Per-attempt timeout that also covers the body read; streamed response size cap (counted after decompression, so missing or lying `content-length` cannot get past it).
  - Retry with full-jitter backoff on 5xx, timeouts and network failures (GET/PUT/DELETE by default), and on 429 for any method unless `retry: false`. Retry-After accepted as seconds or IMF-fixdate; a wait above the cap stops retrying.
  - Redirects are never followed (`redirect: "manual"`; a 3xx is a `provider_error`, not retried).
  - Bodies: JSON, form (`URLSearchParams`) or a raw string with the caller's content-type. `responseType: "json"` (default) rejects a non-JSON 2xx; `"text"` returns the string. An error body that is too big or not JSON never changes the error kind (a 401 stays `forbidden` / 401).
  - Auth: a `SecretValue` or a function returning one (picked up again on each attempt); `basicCredentials()` for token endpoints. A credential that is not a valid header value, or a failing `auth` function, gives a ConnectorError without the value or the foreign message.
  - Failures are ConnectorError with endpoint template, status, provider request id and redacted provider code, never the body. The caller's own abort rejects with the abort reason instead.
  - One log line per attempt through the redacting logger: `info` on success, `warn` with `retry_in_ms` when retrying, `error` with `final: true` on the last failure; carries kind, status, provider code and request id, lane, provider and connection.
- `http/rate-limit.ts`: sliding-window limiter per bucket `provider:lane:key` (lanes never share a queue). FIFO admission; an aborted waiter is released at once and uses no slot; asking for a different limit on an existing bucket throws.
- `log/index.ts`: `child()` no longer drops a bound context value when given `undefined`.
- `@nichols/connectors/testing/msw`: `useMockServer(...handlers)` and one folder per provider (base URLs, default handlers). An unmocked request is blocked and also fails the test in `afterEach`, even if connector code caught the error; `takeUnhandled()` for tests that expect one.
- Lint: new `no-test-only-import` (msw and `@nichols/connectors/testing*` only in test files and the harness itself).

## Tests
- `client.test.ts` (39): parameters, query, auth, bodies (JSON, form, raw, Basic); refusing path traversal; retries and backoff values; Retry-After (seconds, date, past date, over the cap, malformed); POST and 429 rules; network failures; timeouts; a body that stalls or breaks after the headers; caller abort before and during backoff; status-to-kind mapping without body leaks; redirects; size cap with and without content-length; non-JSON 2xx; option validation; log levels and fields; lane-separated buckets; limiter ordering with a cancelled waiter; MSW blocking an unmocked request to a real provider base.
- `config.test.js`: fixtures for `no-test-only-import`.

## Risks
- The rate limiter is per process; the cross-process control is the Inngest per-connection concurrency key (architecture §6).
- The stall and reset tests use an injected `fetch`: MSW's interceptor does not cope with a stalled stream being cancelled under it.
