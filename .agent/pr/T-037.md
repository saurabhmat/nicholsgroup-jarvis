# T-037: Inngest setup

## Changes
- `@nichols/core/inngest` (`packages/core/src/inngest/`, the path T-003 reserves for the Inngest client):
  - `events.ts`: typed events declared with Inngest v4 `eventType` and Zod; every schema requires `laneId` (`^[A-Z]{1,8}$`) and is strict (ids only, no content): `conn/sync.requested` (connectionId), `action/approved` (actionId), `system/heartbeat.requested`. `LANE_EVENTS` lists them for the test.
  - `index.ts` (server-only): `getInngest()` (created on first use; keys from `getInngestEnv()`; dev mode only for `APP_ENV=local`), `sendLaneEvent()` (validates, then sends name + data only), `inngestRoute(functions)` (GET/POST/PUT; outside local, 503 `jobs_not_configured` when keys are missing instead of serving unsigned requests; functions created on the first request, so builds read no env).
  - `functions.ts`: `platformFunctions()` with `system-heartbeat` (echoes the lane id).
- `apps/web/app/api/inngest/route.ts`.
- Dependency: `inngest` 4.26.2 (pinned) in `@nichols/core`; allowlist updated.

## Tests
- `events.test.ts` (3): events without `laneId` do not compile (`@ts-expect-error`); every lane event refuses missing/invalid lane ids and unknown fields at runtime.
- `route.test.ts` (2): production without keys → 503 for GET/POST/PUT; dev mode only for `APP_ENV=local`.
- Local dev server: `GET /api/inngest` → 200, mode `dev`, 1 function. Not yet run against the Inngest dev server itself: downloading `inngest-cli` (`npx inngest-cli@latest dev`) was blocked by this session's permissions; the registering `PUT` fails until that dev server runs.

## Review (security, Oct 31, 2026; no BLOCKER or HIGH)
- Verified by the reviewer: in cloud mode signatures are enforced (POST, signed PUT, GET → 401 unsigned); `isDev` cannot be flipped by env or headers; functions validate events on receipt (400 without `laneId`); keys never logged.
- M1 (fixed): unsigned PUT could re-register the app at an attacker-chosen URL. Outside local: `enableUnauthedSync: false` and `serveOrigin` = `NEXT_PUBLIC_APP_URL` (test: unsigned PUT → 401, no outbound call).
- M2 (fixed): Inngest keys on a PR Preview would hand signing keys to unreviewed code. The env refuses `INNGEST_*` when `APP_ENV=preview` (tests) and the route is unavailable there; H-003 scopes keys to Production.
- L1 (fixed): `inngest` imports (non-type) and `getInngest` are restricted to the Inngest folder (lint, tests); `sendLaneEvent` validates against the registered schema by name (a forged `validate()` no longer helps); a test checks every function is triggered by a registered lane event.
- L2 (fixed): dev mode needs `APP_ENV=local` and a development build (`isDevelopmentRuntime()` in the env module).
- L3 (fixed): `next dev` and the e2e server listen on 127.0.0.1 only.
- L4 (fixed): `sendLaneEvent` refuses lanes not in `ENABLED_LANES`; NL's own Inngest keys recorded in plan-review §7.
