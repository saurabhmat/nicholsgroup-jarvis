# T-032: Vault token functions

## Changes
- Migration `20261102050000_connection_vault_tokens.sql`:
  - `core.connection_secrets` (private: RLS on, no policy, no grants even for service_role): connection → Vault secret id, lane-consistent FK.
  - Security-definer functions, service_role only, each lane-checked first (same error for wrong lane and unknown connection) and serialised per connection by a row lock:
    - `connection_token_store(lane, connection, secret, expires_at, actor_id)`: connect or reconnect in one call; creates or replaces the secret, sets `active`, audited (`connection.token_stored`, acting user when given).
    - `connection_token_read(lane, connection)`: refused when disconnected; `reconnect_required` may read (to revoke at the provider, T-195).
    - `connection_token_rotate(lane, connection, secret, expires_at)`: refresh; keeps the status; not audited.
    - `connection_token_revoke(lane, connection, actor_id)`: disconnect (QB-8); deletes the secret and sets `disconnected` atomically; idempotent; audited (`connection.disconnected`).
  - Trigger backstop: a connection cannot be marked disconnected directly while a credential is stored.
  - `expires_at` has no default, so callers pass null on purpose.
- Catalog test: new definer functions and the private table on the reviewed lists.

## Tests
- `090_connection_tokens.test.sql` (54): privileges (authenticated/anon cannot execute; internal helpers not callable; mapping table closed to everyone); connect, read, rotate, reconnect from `reconnect_required` and from `disconnected`, disconnect; wrong-lane calls refused and change nothing; input validation; Vault secret count per connection; audit entries with actor and no secret text; authenticated cannot read `vault.secrets`, `vault.decrypted_secrets` or the mapping.

## Risks
- service_role can reach `vault.*` directly (granted by Supabase, cannot be revoked by migrations). Accepted and pinned by a test; T-033 adds the lint rule that confines Vault use to `packages/connectors/src/vault/**` (docs/plan-review.md §7 Nov 2).
