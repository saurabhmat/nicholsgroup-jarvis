# T-052: QuickBooks Reports API

## Summary
Pulls the QuickBooks summary reports (default: P&L and the two aging summaries; see Risks) (ProfitAndLoss, BalanceSheet, CashFlow, AgedReceivables, AgedPayables) for a connection and stores a stripped-down copy in `fin.report_cache`:
- GET only, through the T-051 `QboApi` (rate limit, Vault tokens, lane-bound connection). Nothing is written to QuickBooks.
- Date range, accounting method and class come from `lane_config`. The class filter is used only when the connection's class-tracking flag is on and the report takes it; otherwise the report is fetched unsplit and marked (`params.unsplit`).
- A nightly Inngest schedule (02:00 America/New_York) fans out one run per usable QuickBooks connection of each enabled lane.
- Payroll (D-25 default (b)): payroll account rows and sections are removed, and so is every total that could be subtracted to recover them.
- Tested only against the synthetic MSW fake: aging-by-class, reconciliation state and the report shape are unverified against Intuit (H-035).

## Risks
- No database-side statement timeout (a role-wide `alter role service_role` was removed: it changes every job and may be refused on hosted Supabase; a function-level SET does not bound its own call). The report write has a 30 s client abort and size caps; the remaining gap is in plan-review (MEDIUM).
- No retention for `fin.report_cache` yet: about 5 rows per connection per night. Follow-up task needed (plus purge on a payroll policy change).
- **Fail closed by default (D-27 option C):** `cash_flow` and `balance_sheet` are not fetched or cached until a human decides (`lane_config.finance.reports.kinds`, default P&L + AR/AP aging). With them cached, the aggregate payroll amount could be recovered across reports. The cash view, weekly cash report and tie-out need `balance_sheet`, so they wait on D-27. P&L + aging alone were re-checked for payroll accounts (tested). Final security review HIGH: people on `excluded_entity_ids` are paid through ordinary expense accounts, so while that list is non-empty only the aging summaries are cached (fail closed; list their accounts in `finance.payroll.account_ids` to cache the P&L again).
- The name safety net removes any row whose label looks like payroll (fails safe).
- Everything about Intuit's real answers is unverified (class filter on aging/cash flow, field names, ids on rows).
