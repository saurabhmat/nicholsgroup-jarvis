## What changed
- **0. Run now and env hardening.**
  - The env schema trims `ANTHROPIC_*` and connector values.
  - Model IDs must match `^claude-[a-z0-9-]+$`, and a bad one fails with the variable name.
  - The briefing card shows a fixed failure reason, with an admin hint built on the server.
  - Run now runs inline with a time limit and only one run at a time. A late write is blocked by an abort signal, and a late job proposal is withdrawn.
- **1. Layout.**
  - Row 1: attention (2/3) and the calendar, with Next 7 days collapsed.
  - Row 2: a strip of 5 KPI tiles, with finance caveats.
  - Row 3: news and projects.
  - Coverage moved to Settings → Connections, and the Home header has a status dot. Phone: a single column.
- **2. Needs your attention.**
  - It merges the AI briefing: a summary, the prepared time, Run now and the top 3 priorities.
  - The top 5 items each have Reply and Open.
  - Open goes to `/<lane>/inbox/<messageId>`, and "Open in Gmail" uses the `authuser` URL. This fixes the wrong-page bug.
  - Exclusions come from one classifier. Sync flags are set from headers (`is_bulk`, `is_calendar`, `is_auto`, `is_generated`, `is_auth_pass`); only booleans are stored, never header text.
  - Priority-sender treatment requires Google's own DMARC/DKIM pass for the From domain. The header parser fails closed.
  - An invoice or failed-payment mail is kept despite bulk headers only from an authenticated sender, and never from spam or trash.
- **3. Reply drawer.**
  - A side drawer on desktop, full screen on a phone.
  - The draft is the T-231d draft or an AI draft made on demand (policy-gated, rate-limited, never stored).
  - To, Cc and Body are editable. The subject is fixed as "Re: …", "Sends as" is shown, and a plain-text thread preview sits above.
  - Send proposes and approves the exact edited payload through the T-232 path. A step-up redirect keeps the edits.
  - The duplicate-send guard is in SQL:
    - `act_reply_state` checks per thread;
    - `act.approve` refuses with `check_sent_first`, or `already_replied` for a draft made before the latest verified reply;
    - `insert_proposal` refuses with `reply_already_pending`;
    - a send that may have gone out is recorded as unknown and never as `execution_error`.
  - Drafts are kept in sessionStorage per lane and user, with a TTL, cleared at sign-out. Nothing is kept when the lane doesn't store drafts.
- **4. GovCon news.**
  - Web search through LLMProvider, only with an explicit opt-in (`web_search_20260209`). Any other server block still fails closed.
  - Each item is grounded: the link must be in this response's search results or citations, https only, a public host, and the date confirmed within 48 h.
  - One fetch a day with retries (3 failures, 30 minutes apart), plus an owner Refresh at most once an hour. Both are enforced in SQL.
  - The `web` category, and a monthly spend cap checked in SQL before every model call. A refresh is never booked below its reserve.
  - Each item shows its real link host. The card reads stored data only.
- **5. Auto-refresh.**
  - Every 5 minutes while the tab is visible, and on focus when older than 5 minutes. "Updated N min ago" appears in the header.
  - Paused while the drawer is open, a send is in progress or a field has focus.
  - Expanded sections and an open drawer survive a refresh and a reload. A reload never starts an AI draft by itself.
  - A refresh only re-reads data.
