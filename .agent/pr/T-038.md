# T-038: conn.sync skeleton

## Summary
An Inngest function `conn-sync` (event `conn/sync.requested`) runs one sync for one connection.
- **One at a time per connection.** The concurrency key is the connection id with a limit of 1. A partial unique index on running `core.sync_runs` rows backs this up in the database.
- **Retries.** The function retries up to 4 times. A retryable connector error becomes `RetryAfterError` (capped at 15 minutes); a permanent one becomes `NonRetriableError`.
- **Run log.** Every attempt is logged in `core.sync_runs` (start, then succeeded, failed or cancelled) with redacted error info only. On finish, the connection's `last_sync_at` or `last_error` is updated.
- **Cursors.** Cursors are saved with a compare-and-swap write, so a run never overwrites a newer cursor.
- **Google wired in.** Google is the only provider wired so far: one run does mail and then calendar, using the T-063/T-064 runners. Every other provider fails its runs with `unsupported_op` until its sync task adds a runner.
- **Scope.** The sync only reads from providers and writes to our own database (rule 5). Nothing sends `conn/sync.requested` yet: the scheduler and a "Sync now" button come later.

## Changes
- **`packages/core/src/inngest/conn-sync.ts`** (new). The function re-checks the event, because events can be sent to Inngest directly without going through `sendLaneEvent`. It skips lanes not in `ENABLED_LANES`, then calls an injected `runSync` (core cannot import connectors). `events.ts` gains an optional `trigger` (schedule, manual, webhook, connect), which is only a label on the run row. `index.ts` exports the function.
- **`apps/web/app/api/inngest/route.ts`** registers the function with `connSyncJob` from `@nichols/connectors/sync`.
- **`packages/connectors/src/sync/`** (new):
  - `job.ts`: load the connection for this lane, skip it unless it is active or degraded, open a run row, run the provider, close the row, record the outcome. A failure to write the log never retries a sync that already finished.
  - `store.ts`: the run log and cursor store. A new start cancels a row left open by an earlier attempt of the same Inngest run, or one older than 30 minutes; a second genuine start is skipped as `already_running`.
  - `runners.ts`: the generic `Connector.sync` runner, which saves to stream `default` only after the connector finishes, and the Google mail-then-calendar runner.
  - Also `types.ts` and `index.ts`.
- **`packages/connectors/src/vault/index.ts`** builds the stores from the lane job client. `package.json` adds the `./sync` export.
- **Migration `20261105160000_conn_sync_cursor_put_and_one_running.sql`**:
  - closes any stray `running` rows;
  - adds the partial unique index `sync_runs_one_running_idx`;
  - adds `core.sync_cursor_put(lane, connection, stream, expected, cursor)`. It is security definer with `search_path = ''` and callable by `service_role` only. It writes the `default` stream only, never `mail` or `calendar`. It takes the advisory lock, then checks that the lane is enabled and the connection is usable in that lane, then does the compare-and-swap.
  - No new table or column, so RLS is unchanged.
- **`packages/core/src/db/types.ts`** regenerated. It had been stale since T-063/T-064.
- **pgTAP:** new `180_conn_sync_cursor_put.test.sql`; the `050_catalog` allow-list entry; the `080_connections` fixture (the APK run is now inserted as finished, because the new index fires first).

## Risks
- **Long runs can overlap.** A run longer than 30 minutes can be marked stale and a second sync started. The damage is limited to duplicate provider reads, because the cursor compare-and-swap protects the data. Before the first full Gmail load in staging, set `maxDuration` on `/api/inngest` and keep the stale limit above it, or add a heartbeat.
- **Nothing triggers a sync yet.** Whoever adds the scheduler or a "Sync now" button must check membership and AAL2 on the server, and add an idempotency or singleton key.
- **Inngest keys are needed for jobs to run.** On a deployment without them (PR Previews), the function is registered but nothing is sent.
