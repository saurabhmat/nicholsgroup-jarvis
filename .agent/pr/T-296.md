## Review fixes (second commit): the CSS reasoning
**H1, bubble width.** The bubble's cap is `max-width: min(calc(100% - 1.5rem), 65ch)`. A percentage needs a definite base: the group's `ul` and every `li` are now `w-full` (alignment still comes from `items-start` / `items-end` of those column flex boxes; the bubble is a flex item that shrinks to its content up to the cap). Above them the group item is a stretched child of the log's column list, whose width is the scrolling log's (no `items-*` on the log or the list), so the chain is definite up to the log (pinned by a source test). One word: bubble = text width + padding, far under the cap, aligned left or right. Two lines: text wraps at the cap (65ch or pane width minus 1.5rem, whichever is smaller), bubble = widest line. Long: bubble = the cap, long words wrap (`overflow-wrap:anywhere`, `min-w-0`).

**M2, phone height.** The chrome above the pane (header band, main padding, page header, notice lines) has no fixed size, so the scope measures it after layout: `--pane-h = window.innerHeight - tab bar height - (right column's top + scrollY)`, the pane is `h-[var(--pane-h, calc(100dvh - 8.5rem))]`, so at scroll 0 its bottom edge is exactly `innerHeight - tabBar`, directly above the fixed bar; the messages scroll inside it and the header (with the back arrow) is the pane's first row. Re-measured on resize, visual viewport change and body size change (a notice line appearing). The composer slot no longer pads by the safe-area inset (the tab bar below takes it). The shell was not changed (its `data-slot="tab-bar"` is read). The Channels pane uses the same variable.
