## Acceptance check
- **Strict TypeScript everywhere:** `tsconfig.base.json` sets `"strict": true`, and every package extends it.
- **Shared flat config:** `packages/eslint-plugin/src/config.js`. It is applied to `apps/web` as well (tested in `config-web.test.js`).
- **Rule (a), vendor SDKs and outbound fetch:** `no-vendor-sdk` and `no-external-fetch` allow these only in `packages/connectors`.
- **Rule (b), `executeWrite`:** `no-restricted-names` allows it only in `packages/modules/approvals`.
- **Rule (c), the Supabase secret client:**
  - `no-supabase-secret` and `no-restricted-names` keep the secret client in the lane router.
  - `getSupabaseSecretKey` is allowed only in the lane router and the connector vault.
- **Rule (d), secrets in public names and client code:**
  - `no-public-secret-name` uses `isSecretLikeName` from `@nichols/core/env/secret-patterns` (the T-005 list plus its allowlist). `@nichols/core` is in the root devDependencies.
  - `no-server-secret-in-client` blocks the secret client and secret env accessors in `"use client"` modules.
- **Review extras:**
  - `no-env-result-copy`: no spreading, `Object.assign`, `structuredClone` or logging of env results.
  - `no-free-text-env-read`: covers `FREE_TEXT_VALUE_NAMES`.
  - `no-process-env`: `process.env` is allowed only in `packages/core/env`.
- **Tests:** each rule has failing fixtures in `rules.test.js`. `pnpm test` reports 432 tests passing for `@nichols/eslint-plugin`.
