# T-039: Raw source records

## Changes
- Migration `20261102080000_raw_source_records.sql`: schema `raw` and `raw.source_records` (lane_id, connection_id, provider, object_type, external_id, payload jsonb, payload_hash, source_updated_at, deleted, synced_at). Unique per (connection, object type, external id); composite FK (connection_id, lane_id) to `core.connections`. Private table (RLS on, no policy, no grants to any role, schema not exposed to the API). `payload_hash` (SHA-256 hex) is set by a trigger.
- `core.source_records_upsert(lane, connection, records)`: SECURITY DEFINER, service_role only. The connection must belong to the lane; the provider comes from the connection row. Batch of up to 1000, duplicates in a batch collapse (last wins).
- Content guard in the database (trigger on the table): google / microsoft / notion payloads with a body-named key (any depth, case and punctuation ignored, fails closed past 16 levels) are refused unless `lane_policies.store_content_bodies` is true.
- `packages/connectors/src/raw/`: `guard.ts` (`assertContentAllowed`, `hasBodyField`), `store.ts` (`createRawRecordStore`: `upsertRawRecords`, `sinkFor` for `Connector.sync`), wired in `vault/index.ts` as `rawRecords` (the only place that may name the job client) and exported at `@nichols/connectors/raw`.
- Lint: `rawRecords` and `createRawRecordStore` are restricted names. Regenerated `packages/core/src/db/types.ts`. Catalog test lists the new private table and function.
