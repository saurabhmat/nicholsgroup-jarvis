# T-039: Raw source records

## Changes
- Migration `20261102080000_raw_source_records.sql`: schema `raw` and `raw.source_records` (lane_id, connection_id, provider, object_type, external_id, payload jsonb, payload_hash, source_updated_at, deleted, synced_at). Unique per (connection, object type, external id); composite FK (connection_id, lane_id) to `core.connections`. Private table (RLS on, no policy, no grants to any role, schema not exposed to the API). `payload_hash` (SHA-256 hex) is set by a trigger.
- `core.source_records_upsert(lane, connection, records)`: SECURITY DEFINER, service_role only. The connection must belong to the lane; the provider comes from the connection row. Batch of up to 1000, duplicates in a batch collapse (last wins).
- Content guard in the database (trigger on the table): google / microsoft / notion payloads with a body-named key (any depth, case and punctuation ignored, fails closed past 16 levels) are refused unless `lane_policies.store_content_bodies` is true.
- `packages/connectors/src/raw/`: `guard.ts` (`assertContentAllowed`, `hasBodyField`), `store.ts` (`createRawRecordStore`: `upsertRawRecords`, `sinkFor` for `Connector.sync`), wired in `vault/index.ts` as `rawRecords` (the only place that may name the job client) and exported at `@nichols/connectors/raw`.
- Lint: `rawRecords` and `createRawRecordStore` are restricted names. Regenerated `packages/core/src/db/types.ts`. Catalog test lists the new private table and function.

## Tests
- `110_raw_source_records.test.sql` (pgTAP, 200 after round 2): grants and RLS, body detection, hash, upsert/update, batch duplicates, cross-lane connection refused (function and table FK), content guard on and off by lane policy, 1 MB cap, owner at aal2 and anon denied.
- `guard.test.ts` / `store.test.ts` (Vitest): guard cases, SQL and TS lists match, lane-bound and per-record lane/connection/provider checks, no write on any rejection, policy failure fails closed, fixed error messages, batching, sink.
- eslint-plugin config tests for the new restricted names.

## Review
Independent `security-reviewer` and `code-reviewer` ran on b7c50df; findings and dispositions in `.agent/notes/review-T-039-security.md` and `review-T-039-code.md`. Fixed in this PR:
- Content guard is now substring-based on the normalised key (NFKD fold, lower-case, a-z0-9) with a small safe-token list (contentType, contentLength, textColor, messageId, context, ...). monday, gohighlevel and timesolv are content providers (timesolv time-entry metadata is storable; narrative/description is not unless the lane policy allows).
- Forbidden-data guard for every provider (SSN, tax id, account/routing numbers, IBAN, bill/cost/pay rate, salary, PIN, passwords, secrets, tokens), in the trigger and in TypeScript, no echo. Connectors should strip these fields before storing (e.g. QuickBooks `AcctNum`).
- `core.source_records_upsert` validates every element first with its own errors (no DETAIL), requires an active or degraded connection in an enabled lane, and skips stale overwrites (`source_updated_at` ordering guard).
- TS store: 1 MB per record, batches cut at 500 records / ~5 MB, SQLSTATE 22xxx/23xxx/54000 mapped to non-retried `invalid_input`. SQL accepts 1000 records / 8 MB per call (deliberately larger than TS).
- Parity test globs the migration; vacuous tests fixed; new pgTAP (105) and Vitest cases.
- Deferred: stored bodies persist after the policy flips to false (register `raw.source_records` in the T-042 purge); skipping unchanged-hash updates (would freeze `synced_at`); monday/gohighlevel adapters must still reduce to metadata; look-alike (cross-script) keys not folded.

## Round 2 (second security review of 173484c)
- H-1 forbidden-data guard is word-aware (see docs/plan-review.md): whole words, contained text, `*token` words except sync/page tokens, `rate` next to bill/cost/pay/hourly, bare `rate` for timesolv. SQL (`raw.key_words`, `raw.forbidden_*`, `raw.payload_scan`) and TS (`keyWords`, `hasForbiddenField(payload, provider)`) are pinned by the parity test and shared key_words fixtures.
- M-A body names add note, memo, transcript, preview, excerpt, caption; M-B safe tokens add htmllink, webcontentlink, messagestotal, messagesunread, lastmessagetype, lastmessagedate. Denylist-is-a-backstop and the monday/Notion content decision are recorded in docs/plan-review.md.
- M-C one walk and one normalisation per distinct key for both guards, safe tokens removed once then one combined regex, 20000 distinct-key cap (22023, also in TS), BEFORE UPDATE guard skipped when payload/provider/lane are unchanged (the ON CONFLICT path still guards the proposed row and, if changed, the updated row; documented in the migration), 57014 mapped to invalid_input.
- L-1 TS payload cap 680000 bytes of JSON, U+0000 refused as invalid_input. L-2 timestamps must be ISO-8601 with an offset and finite; a null `source_updated_at` no longer overwrites a non-null stored value (skipped). L-3 `stripForbidden()` exported from `@nichols/connectors/raw`.
- Tests: pgTAP now 200 (forbidden/allowed lists, key_words, key cap, 5000-key payload, timestamps, null source_updated_at); Vitest guard/store cases for all of the above.
- Not fixed: all-caps run-together names (`EMPLOYEESSN`) and cross-script look-alikes are not caught (denylist limit; adapters must allowlist); the SQL payload scan is not parallelised and has no per-key timing guard beyond the statement timeout.

## Round 3 (third security review of 3d839ee)
- HIGH-1: linear acronym split, 256-character key limit (22023 / `invalid_input`) checked before normalisation, store order size -> NUL/key length -> guards; timing tests (Vitest, pgTAP).
- MED-1/2: deletions always apply unless a dated incoming version is older than the stored one (an undated delete keeps the stored time); in-batch dedupe orders by `source_updated_at desc nulls last, n desc`. Store gains `upsertRawRecordsDetailed` -> `{written, skipped}`.
- MED-3: joined-key word test, plural stripping, acronym plurals, new contained terms, zero-width stripping, word-end rules for `secret`/`accountno`, new safe token names. Probes in both suites.
- MED-4: custom-field name/value arrays (QBO `CustomField`, GHL `customFields`) bypass key-name guards; every adapter's allowlist projection must drop or allowlist them (docs/plan-review.md).
- LOW-2..4: conservative size for exponent-form numbers, TS timestamp regex identical to SQL (pinned), `payload_key_names` returns `(k, is_deep)`, `stripForbidden` copies own `__proto__`. pgTAP now 281.
- Known, accepted: substring false positives (caffeine, itinerary, sewage), run-together names (`EMPLOYEESSN`, `sSNLast`), cross-script look-alikes, an undated delete loses to a dated update in the same batch.
