# T-007: Synthetic seed framework

## Changes
- `supabase/core/seed/` (plain ESM, runs on Node 22+ with no build, like `scripts/*.mjs`):
  - `rng.mjs`: deterministic RNG: a SHA-256 counter stream keyed by (seed, label), with `nextUint32`, `next`, unbiased
    `int`, `pick`, v4-shaped `uuid`, and `derive(label)` for independent child streams. Not for security use.
  - `data.mjs`: `SEED`, `SEED_EPOCH` (fixed clock), `LANES` (PKG, APK, PKI, NC, NL, P; only PKG enabled; NL on the
    `nl` data plane), `PERSONAS` (owner, admin_technical, finance_operator, viewer, outsider; "Synthetic ..." labels,
    `@example.test` emails, intended memberships for T-012; outsider has none), `ALLOWED_NAME_WORDS`,
    `buildSeedData(seed)` (deep-frozen, adds a per-persona deterministic id).
  - `sql.mjs`: `lit` / `json` / `values` literal helpers.
  - `guard.mjs`: synthetic-only guard (emails only on exactly `example.test`, anywhere including comments; domain-like
    tokens in literals only on reserved names; capitalized words in literals only from lane names/codes and persona
    labels; denylist of the real people and company domains from the planning docs).
  - `lexer.mjs` (review fix): single-pass SQL tokenizer used by the guard and the generator's statement checks.
  - `sections/index.mjs` (ordered registry, with placeholders for T-010/T-011/T-012) and `sections/auth-personas.mjs`.
  - `generate.mjs`: builds `seed.sql` from the sections, validates the registry (kebab-case unique ids, one-line
    descriptions, array of `;`-terminated statements), rejects non-deterministic SQL (`now()`, `random()`,
    `gen_random_uuid()`, `gen_salt()`, `current_timestamp`, ...), runs the guard (fails closed), writes atomically;
    `--check` fails on drift.
- `supabase/core/supabase/seed.sql`: now generated. Seeds the five personas into `auth.users` + `auth.identities`
  with fixed ids/timestamps, **no password** (empty hash), confirmed email, '' token columns (GoTrue cannot scan
  NULL), no role/lane in metadata, `on conflict do nothing`.
- Root scripts: `db:seed`, `db:seed:check`; `db:reset` = regenerate + `supabase db reset --local --workdir supabase/core`;
  `test` also runs `supabase/core/seed/*.test.mjs`.
- `scripts/test-db.mjs`: runs the seed `--check` before the reset, so pgTAP never tests a stale seed.
- README: "Seed data (synthetic only)" section, including how later tasks add a section (with a T-010 example).
- `docs/backlog.md`: T-007 `status: done`. Notes in `.agent/notes/T-007.md`.
- No migrations and no new tables: `core.lanes`, `core.lane_config`, `core.users`/`memberships` stay with
  T-010/T-011/T-012, which each add one section file and a registry line.

## How later tasks add seed data
Add `supabase/core/seed/sections/<id>.mjs` exporting `{ id, description, build(ctx) }`; use `ctx.data` (lanes,
personas with ids, epoch), `ctx.rng` (the section's own stream) and the `sql.mjs` helpers; register it in
`sections/index.mjs` after the sections it references; `pnpm db:seed`; commit `seed.sql`. Sections get independent
RNG streams, so adding one never changes existing ids. New synthetic capitalized words go into `ALLOWED_NAME_WORDS`.

## Security notes / risks
- Seed SQL is applied only by `supabase db reset --local` here; README says never `--include-seed`, `--linked` or
  `--db-url`. The seed's first statements set `standard_conforming_strings = on` and fence: abort when any auth user is
  not on `example.test`. The fence does not help after a reset of a linked DB (the reset wipes first); that path is
  closed only by H-022 (see `docs/plan-review.md` §6, T-007 review).
- H-025 (optional Preview DB seeded with this): the personas carry **verified** `example.test` email identities. If
  that project ever enables automatic identity linking or an OAuth provider that can assert an `example.test`
  address, someone could attach to a persona. Keep email/OAuth sign-in for those addresses impossible there, or seed
  Preview without identities.
- The guard is a heuristic (allowlist of capitalized words + denylist + digit patterns); it cannot catch lower-case
  names or names assembled with `chr()` / `||`. Reviews of new sections still matter (stated in the README).
- Persona memberships in `data.mjs` (owner on all six lanes, the others on PKG only, outsider none) are a proposal for
  T-012, not enforced anywhere yet. **Note for T-012:** no persona is a member of a non-PKG lane only, so a true
  cross-lane denial test (member of lane A cannot read lane B) needs e.g. a viewer on APK only. T-012 decides; no
  personas were added here.
- Local email sign-in is disabled in `config.toml` (`email_provider_disabled`), so OTP flows for the personas start
  working only once T-018 enables the email provider locally; tests can use the admin API meanwhile.

## Review (security + code, Oct 28, 2026; no BLOCKER/HIGH in the diff) — fixes in `T-007: review fixes`
- **Security M1 (fence):** fixed. Generator-owned header: `set standard_conforming_strings = on;` and a `do $fence$`
  block that raises `synthetic seed refuses: non-synthetic users present` when any auth user has a null or
  non-`example.test` email. Only the exact header is exempt from the guard's lexer checks (emails and denylist still
  cover it). pgTAP `throws_ok` proves it fires; a node test pins the pgTAP copy to the generator's exact text; checked
  live: re-applying `seed.sql` is idempotent, and it aborts with a foreign user present. README: never
  `--include-seed` / `--linked` / `--db-url`. T-171 acceptance: `migrate-staging.yml` must not use `--include-seed`.
- **Security M2 / code required 1 (lexer):** fixed. New single-pass `lexer.mjs` ('' escapes, `--` to \n or \r, nested
  `/* */`, `$tag$`, `E''`, `U&''`, quoted identifiers; throws on unterminated). Section output with `$`-quoting, `E''`
  or `U&''` is rejected; descriptions with any control character are rejected; names are checked in literals,
  comments and quoted identifiers. Tests for the reviewer's bypasses (`values("a\n-- '", "Jane Doe")`, `\r` + SQL in
  a description, dollar-quoted name) plus lexer unit tests.
- **Code required 2 (non-determinism):** fixed. Checked on lexed code (comments removed, quoted identifiers unquoted):
  `now /* */ (`, `"now"(`, `gen_random_bytes(`, `random_normal(`, `setseed(`, plus literals `'now'`, `'today'`,
  `'tomorrow'`, `'yesterday'`. Section JSDoc and README: set every now()/random-default column explicitly.
- **Code required 3 (derive collisions):** fixed. RNG keys are `[seed, labelPath[], block]` JSON-encoded; test proves
  `derive("b/c")` != `derive("b").derive("c")`. (All generated ids changed once; `seed.sql` regenerated.)
- **L1:** fixed. Unicode capitals (`\p{Lu}`), Unicode-safe email match (anything but exactly `example.test` fails),
  SSN-like and 9+ digit runs in literals (UUIDs excepted). README calls the guard a heuristic.
- **L2:** fixed. `standard_conforming_strings = on` in the header; `json()` throws on undefined, functions, symbols,
  non-finite numbers and non-plain objects; `lit(undefined)` now throws (pass `null` explicitly).
- **Section dependencies:** fixed. Lanes get ids under `lane:<code>` like personas under `persona:<key>`; rule
  (cross-section ids live in `data.mjs`, else natural keys in SQL) in `buildSeedData` JSDoc, section JSDoc and README.
- **pgTAP scoping:** the persona `set_eq`, identity, distinct-id and epoch checks are scoped to `example.test`.
- **PR notes:** T-012 cross-lane persona note and the H-025 identity-linking caveat added above.
- **H-022:** `--project-ref`, `--include-seed`, `--include-all` added (kept `--project-id`).
