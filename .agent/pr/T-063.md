# T-063: Google OAuth + Gmail metadata sync + live body

## Summary
- Google registered as an OAuth provider (`/api/connect/google/start` and `/callback` through the existing generic routes): authorization code + PKCE, `access_type=offline`, `prompt=consent`, `include_granted_scopes=false`, scopes exactly `gmail.readonly`, `calendar.readonly`, `drive.readonly`. The callback verifies the granted scopes (write scope or missing scope refuses; a refresh token is required), takes the verified primary address from Gmail's profile into `core.connections.external_account_id`, and refuses any address that is not in `lane_config.mailboxes` (an empty list also refuses, before the code is exchanged). Tokens live only in the Vault; refresh is single-flight with compare-and-swap; `invalid_grant` is `reconnect_required`; revoke at Google is an approvals-only writer.
- Gmail `MailProvider`: first load = `messages.list` + `format=metadata` get (fixed headers); incremental = `users.history.list` from a connection-bound composite cursor (404 -> `fullResyncRequired`); deletes -> removals; labels -> folder/labels/flags per the T-062 mapping; snippet dropped at parse. `readBody` = live `format=full`, MIME walk (text/plain preferred, HTML to text, attachments skipped, `maxChars`), `UntrustedBody`, never persisted. `search` quotes the query as one phrase. `watch/renew/stop` = polling (push is T-065). `prepareWrite` per the interface; no execute path; the API client is GET-only; Google hosts are allowlisted.
- Persistence: new `core.sync_cursors` and `core.comms_mail_apply_page` (page + cursor in one transaction, removals first, upsert only when `source_updated_at` is not older, classifier columns untouched); `mailSync.run(laneId, conn)` is the sync entry point (Inngest wiring waits for the connector sync job).
- Env: `GOOGLE_REDIRECT_URI` (default localhost only in local dev; https elsewhere); `.env.example` updated.
