# T-236: AI output limit (briefing and GovCon news survive a cut-off reply)

Branch `agent/T-236`, from `agent/T-235`. Push and merge `agent/T-232`, `agent/T-192`, `agent/T-234` and `agent/T-235` first.

**Why.** In production (Nov 12, ~7:28 PM IST) GovCon news showed "News could not be fetched: the AI answer could not be used", and the briefing failed the same way. The cause is the output limit: current models always think, and thinking counts toward `max_tokens`. The calls had 4000 (news) and 3000 (briefing) tokens, so the reply stopped with `stopReason: max_tokens` before the JSON was complete.

## What changed
- **Output limit in lane_config.** `news.max_tokens` and `briefing.max_tokens`, default 8000, allowed 2000..32000.
- **A cut-off reply is never parsed.** On `stopReason: max_tokens`:
  - one retry with 1.5x the limit (12000 by default), at effort "low" (less thinking, so a shorter call);
  - news asks for at most 4 stories with a "why" of at most 150 characters; the briefing asks for at most 3 lines, priorities and drafts;
  - the half reply is not sent back;
  - the retry runs only while it can still finish in time (news: 30 s into the fetch; briefing: 40 s, as before);
  - a second cut-off, or no time left, is recorded as the new fixed code `output_truncated` ("the AI answer was too long" / "The AI reply was too long", with an admin hint naming the lane_config setting).
- **Briefing: one retry in all.** A malformed reply after the cut-off retry is `output_invalid`; there is no third call.
- **News: at most 6 stories, "why" at most 200 characters.** Both are asked in the prompt and enforced on store.
- **Forgiving news validation.**
  - Any `items` array is read (the first 20 candidates). Each bad story is dropped with a reason code: `invalid_shape`, `bad_link`, `ungrounded`, `blocked_domain`, `empty_text`, `bad_date`, `undated_extra`, `duplicate` or `over_limit`.
  - The fetch fails (`no_valid_items`) only when none is left. An empty list is `no_valid_items`, not "could not be used".
  - The grounding, https and blocked-domain rules are unchanged.
  - One undated story is still kept as "date unknown" (earlier decision); further undated ones are dropped.
- **Cost.**
  - The reserve covers one attempt: $0.99 with the default prices (was $0.81; the limit went from 4000 to 8000).
  - The rare retry is not reserved, because SQL books every attempt at no less than its reserve, and reserving it would have charged every fetch $2.16.
  - The stored estimate adds up both calls' tokens and searches, so the cap can be passed at most once per lane per month, by one fetch's cost above its reserve (about $1.17).
  - A retry that throws keeps at least the reserve.
- **Logs (codes and counts only).**
  - `news.model_call` and `briefing.model_call`: attempt, stopReason, output tokens, max tokens, searches.
  - `news.validated`: kept, dropped and reason counts.
  - Also `news.retry_skipped`, `news.model_failed` and `news.output_unusable`.
  - Never a headline, link, mail text or reply.
- **The hourly Refresh slot.** A failed fetch does not use it. Unchanged SQL (`brief.news_reserve`, `core.news_latest`): after a failed refresh the next is allowed 5 minutes later, and only an ok or partial refresh starts the hour. pgTAP 305 covers it.
- **Contract test against the real API.** `apps/web/lib/ai-contract.test.ts`, skipped unless `AI_CONTRACT=1`, run with `pnpm --filter @nichols/web test:ai-contract`. Inputs are synthetic: a made-up company, `example.test` mail metadata and generic public topics. It checks that the API accepts our structured-output schema and web-search options, that each reply finishes inside the limit, and that it passes our validation.
- **Scheduled briefing time limit.** The run now has a 100 s abort, under Inngest's 120 s `maxDuration`. A slow run is saved as a timeout and its claim closed.
- **A context-window stop is not retried**, because a higher output limit cannot fix it.
- **No structured output for news.** Web search always returns citations, and the API refuses citations together with `output_config.format`. News keeps the tolerant JSON extraction.

## SQL
None. `brief.news_digests.failure_code` accepts any `^[a-z][a-z0-9_]{0,39}$`, briefing failure notes accept `^fail:[a-z_]{1,40}$`, and the new lane_config keys have defaults. **No production SQL is needed for T-236.**
