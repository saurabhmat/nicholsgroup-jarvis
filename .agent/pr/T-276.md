# T-276: faster navigation (menu clicks and page loads)

## Why
Saurabh (Nov 23): "the app loads slowly ... clicking on the menus and navigating should be faster". The audit in the backlog (read-only, nothing measured) found where the time goes: the module gate (T-265) made every gated page wait for two reads before the page started its own; Home read the lane settings 5 times and Coverage twice per render, started Finance late and waited for the Microsoft reply check; Settings waited for its longest chain before showing anything; the four placeholder pages were fully dynamic; a typed address or reload painted nothing. No check was weakened (see "Safety").

Each gated page's route file starts its own loader before returning the gate: `startInbox`, `startCalendar`, `startFinance` (`components/inbox-page.tsx`, `calendar-page.tsx`, `finance-page.tsx`; a request-scoped `cache()` keyed by lane and the searchParams promise, so the page and the starter share one run). Tasks (Projects) only needed the early `loadLane`. The page below the gate is still rendered only after the gate answers and still awaits its own `loadLane`.
2. **Home** (`components/home-page.tsx`): (a) the header waits only for `loadLane`; the Ask Jarvis button reads the module list in its own boundary (`AskJarvis`); (b) new `lib/lane-reads.ts`: one `cache()`-wrapped `laneConfigRow` and `coverageRows` per (request, lane client), used by the gate, Coverage, the briefing, GovCon news and the brain lane facts (each still takes only its own keys; the gate keeps only `enabled_modules`, `limit_to_enabled_modules`, `news`; news still reads the config only for an owner; a job that names an owner reads Coverage for that owner directly); (c) `startFinance` starts `loadFinance` as soon as the module list says Finance is used; (d) the Microsoft reply check starts at once and only the attention rows wait for it, in their own Suspense boundary, behind the same rows drawn without Microsoft Reply (the fail-closed state); (e) the phone setup banner was already in its own Suspense boundary with a reserved slot (verified, no change needed).
3. **Settings** (`components/settings-page.tsx`): the header and a neutral card show at once. All loaders start together as before (with the one guards object), and the connect result and origin notice, Connections, GovCon news and AI brain each stream in their own boundary. 4. **Placeholders** (`components/module-page.tsx`, `external-chat-page.tsx`): Claude, ChatGPT, Contacts and Messages draw their heading and card with no read (they are plain functions), and only the eyebrow (company name) comes from a small async child, `LaneName`, which is also the lane check, so `notFound` / `redirect` still fire on every navigation. 5. **Layout** (`app/[laneId]/layout.tsx`): the Suspense fallback is a static `ShellFallback` (side-menu column plus `PageSkeleton`); it reads no params, cookies, headers or clock.
6. **Inbox** (`lib/inbox.ts`): the label read (Coverage) does not need the message ids, so it starts together with the list and is ignored when the list is empty (one extra read for an empty list). **Calendar** (`lib/calendar-page.ts`): status, accounts and events start together; the last two are ignored (errors too) unless the status is "connected".

## Safety (what a security reviewer should look at first)
- Reads now START before the gate has answered, on the gated pages (Inbox, Calendar, Finance). Each of those loaders opens the lane through the guards first (`requireLane`: session at AAL2 and membership) and runs no query if that fails (tested: a refused lane gets a 404 and only the lane check is asked). Their output is used only by the page below the gate, which is rendered after the gate and after `loadLane`. For a hidden module, the reads run and are thrown away (the hidden module is tidiness, not a permission: RLS and the lane gate are the real checks). No data reaches the response.
- Early promises have no-op catches so a redirecting gate cannot cause an unhandled rejection; every consumer still awaits the same memoised promise and sees the failure (AuthError becomes redirect or 404 in `loadLane`).
- The gate now reads the whole `config` object through the shared reader and takes three keys out of it; the answer object carries only those three (asserted).
- `startFinance` on Home reads Finance for a lane the person may not have: only if the gate (which fails open to "show everything" for a refused lane) says visible, and the finance loaders refuse without a lane check; `loadLane` gives the 404.
- Settings: the nav uses the same role answers the loaders use (`requireRole` is memoised per role set), so a role never sees a chip for a section its loader would refuse; the reverse case (a chip with an empty section) is possible only for a role that has the right but no data (see Risks).

## Risks
- Settings: a person who holds the role but whose loader returns nothing (for example AI brain when the brain view is missing, or Connections for an administrator whose company shows no provider and no coverage) can see a sub-nav chip whose section does not draw. Chosen on purpose (the nav no longer waits for the slow loads); LOW, cosmetic.
- Home: on a company with a Microsoft mailbox, the Microsoft Reply button appears a moment after the rows (the rows are first drawn in the fail-closed state).
- An early-started read for a module a company hides is wasted work (no data is shown).
- Inbox: one extra Coverage read when the list is empty.
- No hosted measurement was possible (local e2e reset is not allowed); the numbers above are logical levels, not milliseconds.
- Security-reviewer and code-reviewer subagents could not be run from this session (no agent tool). Please run them before merging.
