# T-064: Google Calendar sync

## Summary
- `CalendarProvider` for Google over the same OAuth connection (calendar.readonly already granted). Discovery by `calendarList` (default: primary + selected owner/writer calendars; `lane_config.calendar` can add read-only calendars, set an explicit list, or change the 365-day look-ahead; decision D-26 with a safe default). Sync: `events.list` with `singleEvents=true`, a `fields` mask without the description, one composite per-connection cursor (`g1.<conn>.c:...`, a syncToken per calendar, page tokens, full-load window), first load bounded by min(180 days, lane retention) back and the forward window, `showDeleted=true` on full loads, 410 -> `fullResyncRequired` for the whole connection, 404 drops one calendar, forward-horizon reload at half.
- Records: all-day dates with exclusive end and DST-correct local-midnight instants in the calendar's zone, recurring instances (series id, original start), cancelled stubs (status only; the apply merges them without nulling stored fields), attendees/organizer limited to addresses and names (capped), https-only meeting link, `source_url` = htmlLink, `source_updated_at` = Google `updated`, never a now() fallback. No description is ever requested by sync or stored; `readBody` is a live `events.get` with `fields=id,description`, `UntrustedBody`.
- Calendar id encoding (decided): `#` and every other unsafe byte as `=XX`; primary stored as `primary`.
- Persistence: `core.cal_events_apply_page` (definer, service_role only, advisory lock, compare-and-swap on every chunk, stub merge, version guard) and stream `calendar` in `core.sync_cursors`; `calSync.run(laneId, conn)` exported from `@nichols/connectors/google` (no Inngest wiring yet).
- Surface: www.googleapis.com added to the Google host allowlist, but the API client only reaches three Calendar path templates there (anything else is refused before a token is read); GET only; separate rate-limit bucket.
- Refactors: `createProviderGuard` (shared by Gmail and Calendar), `index-rpc.ts` (shared by both stores), the contract harness gained `removedEventsAreStubs`, `mail.contract.test.ts` became `comms.contract.test.ts` (mail + calendar).
