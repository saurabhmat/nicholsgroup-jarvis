# T-247: per-person mail privacy and several Google accounts per user

Approved by Saurabh on Nov 14, 2026 (decisions D-43 to D-47; D-47 amends D-33 in `docs/backlog.md`). Every member sees only their own mail,
admin_technical included. Mail, calendar, briefings, drafts and email approvals belong to the owner of the mailbox. QuickBooks, Finance, news and
Projects stay shared in the lane. Admins (owner, admin_technical) still see connection health, never content.

## Changes
- **Ownership.** `core.connections.owner_user_id` (Google/Microsoft rows only; set at connect to the signed-in user; immutable once set; backfilled from
  `created_by`). New view `own_mail` for owner, admin_technical and viewer. `core.mailbox_ids` / `core.may_brief` / `core.mail_reader` helpers.
- **Privacy in RLS and every reader.** `comms.message_index` and `cal.event_index` need AAL2 + own_mail + the row's connection owned by the caller.
  Readers filter explicitly too: `home_meetings`, `home_mail_attention`, `home_calendar_status`, `briefing_coverage`, `briefing_events`, `briefing_threads`,
  `inbox_messages`, `inbox_message_ref`, `act_reply_state`. The old `comms` / `calendar` / `briefing` views no longer grant anyone else's content.
  The assistant's mail and calendar tools require `own_mail` and return only the caller's mail.
- **Briefings per person.** The 06:30 job and the refresh run per user who owns an active mailbox; every job read names the owner (`p_owner`, honoured
  only for service_role); live body reads check the owner; the guard trigger, policies and claim functions use `own_mail`. Run gates are per owner; the
  daily cost cap stays per lane.
- **Drafts and email approvals.** Email rows in `act.proposed_actions`, `status_history`, `execution_claims` are visible only to the mailbox's owner;
  `act.approve` / `reject` / `claim_execution` / `insert_proposal` require the caller (or proposer) to be that owner (other users get the same `not_found`
  as for an unknown id). admin_technical may approve their OWN email (write role); a viewer may not. Non-email types keep today's rules.
- **Connect flow (native Google).** Any member with `own_mail` connects their own Google account (`core.oauth_state_create/consume`, `connectRolesFor`);
  QuickBooks stays owner/admin_technical. `lane_config.mail.allowed_domains` (default `[]` = fail closed) is checked at connect and on every Google call
  and in the email writer; the exact `mailboxes` list narrows it (both must allow). `mail.self_connect_domains` is in the schema, unused. A Google account
  already connected here by another person is refused; only the owner can reconnect. Composio: sets the owner; its connect is **switched off for a
  lane that sets `mail.allowed_domains`** (it replaces one account per lane per toolkit, so it can't be per-person yet).
- **Settings.** "Your Google accounts" (connect/reconnect your own, several allowed) plus other people's accounts as status-only rows for admins.
- **Decision log.** D-47 (amends D-33) and D-43 to D-46 in `docs/backlog.md`. Builder decisions: `.agent/notes/T-247.md`.

## Risks
- **Part 25 is NOT safe before the deploy** (see below). Between the SQL and the new app, nobody sees mail on Home or in the Inbox.
- A Google/Microsoft connection with no owner is invisible to everyone (fail closed). Part 25 refuses to finish if one exists after the backfill.
- Lanes other than PKG that relied on the exact `mailboxes` list alone must add `mail.allowed_domains` or Google connects/calls are refused (fail closed, by design).
- The assistant gate still denies admin_technical (spec), so Saurabh has no assistant mail tools; the daily briefing cap (6 per lane and day) is now shared by two people.
- `connections` RLS lets the connections view read other people's account address and status (health) as before; that now includes `owner_user_id`.
- No NOT NULL-style DB constraint for the owner on mail rows (see notes: it would break ~20 fixtures and fail later updates); enforced in code and checked in part 25.
