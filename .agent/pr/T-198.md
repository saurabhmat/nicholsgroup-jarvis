# T-198: temporary QuickBooks connect and health controls

## Summary
For the Nov 12 QB-1 – QB-20 sandbox run, until T-045 (connection health page, D-21) replaces it. On a lane's Settings page, a "Temporary: connection test" section with **Connect QuickBooks** (starts the existing T-050 connect flow) and **Check connection** (a new authenticated route that runs the T-050 CompanyInfo health check for that lane's connection). There is no disconnect button (D-24: revoking a grant is an approvals-only write).

## Changes
- `apps/web/app/api/connection-test/qbo/check/route.ts` and `apps/web/lib/connection-test.ts`: `POST /api/connection-test/qbo/check?lane=PKG`, same-origin only.
  - Guard: `requireLane` (a lane that is not the caller's, or does not exist, is **404**), then `requireRole(lane, owner | admin_technical)` at AAL2 (another role or AAL1 is **403**, no session **401**).
  - Off unless `lane_config.pilot.connection_test_enabled` is `true` (read with the caller's own lane client; anything else, or a read error, is off): **404**. A wrong role still gets 403 first, so the switch reveals nothing to other roles.
  - Response: only `{ status, checked_at, intuit_tid }`, `status` one of `ok`, `reconnect_required`, `not_connected`, `error`. Never a token, the realm id or company data (the handler copies exactly three fields, so extra data from the check cannot leak). `Cache-Control: no-store`.
- `packages/connectors/src/quickbooks/connection-check.ts` and `src/connection-test.ts` (new subpath `@nichols/connectors/connection-test`): finds the lane's non-disconnected QuickBooks connection (`ConnectionStore.findConnection`, read-only) and calls the connector's `health`. One GET to Intuit; no write, not even a status update (rule 5). The subpath exposes only `checkQuickBooksConnection`, not the connector or the writer.
- `apps/web/components/settings-page.tsx`, `connection-test-section.tsx`, `connection-check-button.tsx` (client), `app/[laneId]/settings/page.tsx`: the section is drawn only for owner or admin_technical at AAL2 when the lane switched it on; the page still calls `loadLane` first. Design tokens and the shared `@nichols/ui` Card, Alert and Button only: no hard-coded colours. "Connect QuickBooks" is a same-origin form POST to `/api/connect/qbo/start?lane=<lane>`. The client renders only the parsed three fields (`lib/connection-check-view.ts`).
- `packages/core/src/lane-config/index.ts`: `pilot: { connection_test_enabled: boolean (default false) }`, optional and strict. No SQL change (the database only scans lane config for secrets).
