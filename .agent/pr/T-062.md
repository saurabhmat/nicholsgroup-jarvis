# T-062: Mail/calendar/docs provider interfaces + mocks

## Summary
- `MailProvider`, `CalendarProvider`, `DocumentProvider` interfaces (`@nichols/connectors/comms`) with Zod schemas whose mail and event records map 1:1 onto the T-061 `comms.message_index` / `cal.event_index` columns (strict; no body/snippet/description field exists).
- Sync model: `sync(laneId, conn, cursor|null, opts) -> {upserts, removals, nextCursor, hasMore, fullResyncRequired}`; per-connection opaque cursors; calendar instances are expanded, cancelled stubs have no times.
- Live content: `readBody` returns an `UntrustedBody` (trust "untrusted", text hidden from JSON/inspect/spread) in a `SourceResult` with freshness "live". Document search returns links and metadata only.
- Watch/renew/stop with `push` or `polling` mode.
- `prepareWrite` returns a `ProposedPayload` for `email.send` / `email.save_draft` (approvals spec §8 payload); calendar and document writes are typed but `unsupported_op`. There is no execute path on any provider (closed member list, tested); execution stays in `ConnectorWriter` (`@nichols/connectors/writer`).
- Provider selection stays with the connection row's provider (no lane_config field); selection by (lane, provider) lands with T-063.
- `createMockComms` (synthetic, deterministic) and `describeCommsContract` (reusable suite for the Google/Microsoft providers).
