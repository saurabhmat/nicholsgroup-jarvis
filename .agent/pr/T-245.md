# T-245 hotfix: Finance page crash after T-244

## Cause
Production `/PKG/finance` threw `TypeError: h.PERIODS.map is not a function`. The server Finance page imported `PERIODS` from `@nichols/ui`, and the ui index re-exported it from `period-toggle.tsx`, a `"use client"` module. A value exported from a client module reaches server code as a client reference, not the array. Vitest ignores directives, so the T-244 unit tests passed. The page crashed only in the real Next build.

## Changes
- **PERIODS:** moved to `packages/ui/src/lib/periods.ts`, a plain module with no directive. The toggle and the server page both import it from there.
- **Other client constants:** six more constants were exported from `"use client"` components.
  - `POLL_EVERY_MS`, `POLL_FOR_MS`, `STALE_NOTE` and `SYNC_NOW_TEXT` moved to `apps/web/lib/client-constants.ts`.
  - `ENSURE_GUARD_MS` and `REFRESH_INTERVAL_MS` are no longer exported.
  - None of the six was imported by server code (only by tests), so none was a live bug.
- **Static check:** `apps/web/tests/directive-exports.test.ts` parses every `.ts`/`.tsx` file under `apps/web/{app,components,lib}` and `packages/` with the TypeScript compiler.
  - A `"use client"` module may export only components (functions, classes, memo/forwardRef/lazy) and types. Constants, enums and value re-exports fail.
  - A `"use server"` module may export only async functions.
  - A module with no directive may not import or re-export a non-component value (anything not PascalCase, or an ALL_CAPS name) from a `"use client"` module. It resolves `@/…`, relative paths, `@nichols/ui` and `@nichols/ui/components/*`.
  - I checked that it fails on main's toggle and ui index, so it would have caught this crash.
- **Per-card error boundaries:** each Finance KPI card is now its own component (CashCard, ArCard, BillsCard, NetIncomeCard). Each card, and each section (aging, cash by account, controls, reports), renders inside `CardBoundary` (`apps/web/components/card-boundary.tsx`).
  - The error boundary shows "Could not load. Reload in a minute." for that card only. It logs only the card label and the error's name.
  - The Suspense fallback inside it is a neutral "Loading…", because React streams large sections after the page shell. A "could not load" fallback would flash on a healthy page.
  - Subscriptions has no figures and is not wrapped.

## Review fixes (security: no BLOCKER/HIGH; code: no BLOCKER/HIGH)
- **Period switch:** each boundary is keyed on the period, so a card that failed recovers when the period link changes. Before, it stayed failed until a full reload. A test covers this, and it fails without the key.
- **Finance error page:** `app/[laneId]/finance/error.tsx` is a route-level error page ("Finance could not load", with a Try again button) for failures outside the cards: the header and period links, data loading, Subscriptions. The original crash was in the header, which no card boundary covers.
- **Check hardened:**
  - `export default X` from a client module must name a component (an async function for server modules).
  - Every `@nichols/*` import resolves through the package's `exports` map, and an import the check can't resolve now fails instead of being skipped.
  - The scan covers all of `apps/web` (including `proxy.ts` and `instrumentation.ts`) and `packages`.
  - The text prefilter is gone.
  - I checked again that it fails on main's version.
- **Logging comment corrected:** the boundary's own log carries only the card label and the error's name. React's default caught-error log still prints the error in the browser console. In production, Next replaces server component messages with a digest.

## Tests
- `components/finance-page.ssr.test.tsx`: renders the Finance view with `react-dom/server` (streaming, as Next's SSR does). Every card, section and period link appears with its figures. A card that throws is contained, with one SSR error and the rest of the page rendered.
- `components/card-boundary.test.tsx`: on the client, a failing Net income card shows "could not load" while the other cards show their figures. The log line carries no message or figure.
- `tests/directive-exports.test.ts`: self-tests of the rule shapes plus the whole-repo scan.
- The Finance fixtures moved to `components/finance-page.fixtures.ts` (test-only) and are shared by the three Finance test files.
- **Results:** `pnpm typecheck`, `pnpm lint` and `pnpm test` all pass. `pnpm --filter @nichols/web build` succeeds, and `/[laneId]/finance` is Partial Prerender with no error. The built SSR chunk now holds the `PERIODS` array itself.
- No SQL changed, so pgTAP was not needed and no manual migration part is needed.

## Risks
- **What the unit tests can't prove:** they do not run the React Server Components layer, so the static check is what guards against client references. A server component error is serialized to the client and rethrown inside the card's boundary. That containment is reasoned, not tested end to end (no Playwright or `next start` run). The real proof is the production page after deploy.
- **What the boundaries don't cover:** failures outside the cards go to the new Finance error page, not the generic one.
- **Without JavaScript:** a card that failed during server rendering shows "Loading…" until the page hydrates. Without JavaScript it stays "Loading…".
- **Directive check heuristics:**
  - A component must have a PascalCase name, and an ALL_CAPS name counts as a constant. A component named like `UI` would be a false positive.
  - Dynamic `import()` and `require()` are not checked.
