## Summary
- **Decisions followed:** D-39 (every file is read in the browser and never stored: no Storage bucket, no raw text in the database, logs or Inngest payloads; only text selected by the user, at most 50,000 characters, is posted and used inside the request) and D-40 (the model call is gated by the new lane-policy category `brain_import` on the home lane, through the existing `core.ai_tool_gate`; refused shows "Not allowed for this company.").
- **Where:** optional "Start faster: import what Claude or ChatGPT already knows" (Import / Skip) on the onboarding intro; Settings -> AI brain -> "Import memories"; the assistant answers "import my memories" with a link (no model). Page `/<lane>/onboarding/import` (so the proxy's H-042 gate returns a real 404 for non-owners, before streaming) and route `POST /api/lanes/:laneId/brain/import` (owner + AAL2 + brain view; `extract`, `propose`, `save`, `discard`, `page_propose`, `page_save`; Zod strict bodies).
- **Pipeline:** instruction-like sentences are removed from the text before the model sees it; the fast model (no tools; text only inside the T-102 untrusted wrapper) returns candidate JSON; targets and sections are limited to a fixed list; a quote is kept only if it appears in the text and is at most 300 characters; sensitive-number and credential screens on facts and quotes; instruction-like facts are dropped; possible Nichols Law content is flagged, unticked, no quote. Candidates are stored through `brain.import_create` (fact + quote only). Checklist: all unticked, grouped by target, editable. Ticked facts become the interview's diff card; Save re-plans from the current pages and refuses unless it equals the proposal; then the import is finished (candidates deleted) and the matching setup sections get `completed_at`.
- **Brain .zip:** read in the browser with fflate 0.8.2 (pinned, no dependencies, added to the allowlist): 10 MB file, 200 entries, 1 MB inflated per page (bomb), 20 MB total, 4 KB streaming slices, `..`/absolute/drive paths refuse the zip, only the four pages are decompressed. About-Me, Preferences, Work and the Personal Assistant file map to their pages as section diffs, no model, each saved by its own click.
- **Without AI keys:** paste/JSON shows "Needs the AI to be configured"; the .zip works.

## Risks / judgement calls
- Completion mapping: a setup section is marked done when a Save put something into a page section that one of its questions writes (bank targets). One Priority-order fact therefore completes both B-1 and B-2; sections the bank does not ask about (Goals right now, Terms and conventions) complete nothing.
- Not importable in T-220: Scope and Timezone (checked answers), the PA's Drafting rules and Rules, other Employees files, Projects, Skills.
- The instruction screen is deliberately broad (it also drops lines mentioning passwords, permissions, API keys, "use the tool ..."); a legitimate fact can be dropped and is counted in the note.
- `possible_nl_content` is a heuristic (the Nichols Law name plus legal-matter words); it flags and never blocks. Saving text that names Nichols Law is refused, like the interview.
- Rate limits: the model call consumes one of the 30 gate calls per minute; `brain.import_create` allows 20 imports per user per hour.
- Edited text is not stored on the candidate row (the row is immutable); the final text is re-screened on propose and save.
