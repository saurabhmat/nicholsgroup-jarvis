# T-274: Calendar page, the person's own Google and Microsoft calendars together

## Changes
- `supabase/core/supabase/migrations/20261129100000_calendar_events.sql`: `core.calendar_events(p_lane, p_from, p_to)`. Security invoker, stable, empty search_path, own mailboxes (`core.mailbox_ids(auth.uid(), p_lane)`), window 1 second to 43 days (22023), nulls 22004, cancelled left out, de-duplicated like `core.briefing_events` (adds `connection_ids` of every copy and the provider), no description or attendees. - `apps/web/lib/calendar-time.ts` (pure): URL parsing, windows (Sunday weeks, month = covering weeks), New York day math, day splitting, overlap layout, hour range. `calendar-format.ts`: wording. `calendar-page.ts`: loader (`home_calendar_status`, `calendar_events`, the caller's own native Google/Microsoft connections for the legend, filtered by `owner_user_id`), row validation (https-only links), `calendarFor` (error gives `unavailable`).
- `apps/web/components/calendar-page.tsx` and the page: Day / Week / Month, Today / previous / next, view switch, legend, per-account colour (chart tokens, gold, success), event details as native `<details>`, all states. Phone: default Day (from the User-Agent, a hint only), Week as a list, Month with dots.
- Production: `supabase/core/bootstrap/manual-migrations/part-32-T-274.sql` and `part-32-T-274-check.sql` (folder is gitignored; not in this commit).

## Risks and notes
- Default Day on phones is chosen from the User-Agent (no script); a desktop browser with a phone UA gets Day. The URL always wins.
- Hour grid positions use wall-clock minutes, so on Nov 1 the repeated 1 AM shows on one row and on Mar 8 the 2 AM row is empty.
- Popovers are `<details>` (no Escape key to close; click the event again).
- The 501-row signal differs slightly from "500 rows"; documented in the migration.
