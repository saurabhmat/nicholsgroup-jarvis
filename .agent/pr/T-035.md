# T-035: OAuth connect framework

## Changes
- `packages/connectors/src/oauth/`: `createOAuthFlow` (start, callback), generic over providers (`OAuthProvider`: endpoints, client credentials, scopes, `identify`); `pkce.ts` (S256, 256-bit state that carries the lane, only its SHA-256 stored); `state.ts` (store over `core.oauth_state_create` / `_consume`); `registry.ts` (empty until T-050 / T-063 / T-066); `handlers.ts` (`createConnectHandlers`: the route logic, testable without Next.js).
- Migration `20261102070000_oauth_states.sql`: `core.oauth_states` (RLS on, no policy, no grants) and two SECURITY DEFINER functions. A state is bound to the user, lane and provider, expires after 10 minutes, is consumed once by an atomic delete, and the owner / admin_technical role at aal2 is checked again on use.
- `vault/connections.ts`: `ensureConnection` creates the row `pending` (or reuses it) and records `created_by`.
- apps/web: `POST /api/connect/<provider>/start` (Origin check, 303 to consent) and `GET .../callback` (303 to a fixed path with a coarse result code, `no-referrer`); both are one-liners over the handlers.
- Lint: restricted-name config for the new modules.

## Tests
- `flow.test.ts` end to end against a mock OAuth server (PKCE, Basic and post client auth, replay, other user, other lane, expiry, secrets never in audit or logs), plus handler tests over the real flow: Origin 403, unknown provider 404, 401 / 403 / 429 / 503, 303 targets and headers.
- `100_oauth_states.test.sql` (pgTAP): other user, other lane, aal1, demoted user, expired, replay.
