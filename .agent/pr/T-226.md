## Summary
1. **Nav.** "Get started" (key and segment `onboarding`) is the first `NAV_ITEMS` entry. The app shell draws it only when the app passes setup progress, and the app passes it only to an owner with the brain view (same gate as the interview route, `loadOnboarding`). Gold badge "N of 10" (live count of completed sections out of the bank's section count) until all are done, then "AI brain" with a check, still first. iPhone: no new tab; first row of More (same badge) and a Home banner "Finish setting up Jarvis (N of 10) →" (phone only, gold left edge). `docs/design/README.md` "Navigation" updated.
2. **Page `/[laneId]/onboarding`.** `BrainInterview mode="wizard"` (`BrainWizard`) over the same bank and the same `/api/lanes/:lane/brain/interview` API (state / propose / save / confirm / activate): no new data path. Intro (three lines, Start); left rail of the 10 sections (done / current / to do, 3px gold edge on current); progress bar; one group per screen with the bank's prompts and hints; "Preview change" shows the exact diff card, "Save & continue" is the only write; "Back" keeps typed answers; "Skip for now" saves nothing and the section stays "Not provided"; known answers show "Already set: … (Edit)"; finish screen lists every section with Edit links, "Run test briefing" disabled ("Arrives with the daily briefing"), "Ask Jarvis" link, and the same Confirm / Activate as the chat. iPhone: rail collapses to "Step N of 10", sticky action bar above the tab bar. `?step=<sectionId>` is checked against the bank twice (server `sectionIdFrom`, client `initialStage`); an unknown value falls back to the first incomplete step; no step and nothing saved shows the intro. After a Save the page calls `router.refresh()` so the menu badge updates.
3. **Settings.** The "Settings are not set up yet" card is dropped whenever any real section renders (`ModulePage placeholder`). AI brain is a compact status list (chip, Edit into the wizard at that step) plus "Continue setup". Composio rows say `Not configured: COMPOSIO_GMAIL_AUTH_CONFIG_ID is not set` (names only; filtered to upper-case identifiers).
4. **Connection errors.** `EnvValidationError` now carries `rules` (variable name to a fixed rule text from an allowlist `ENV_RULE_TEXTS`; any other issue text becomes a generic rule) and `describeEnvError` prints `NAME: rule`. The start handler logs that line, and for a form post (urlencoded / multipart / navigate) redirects 303 to `/<LANE>/settings?error=google_env` (other providers: `connect_env`); the lane must match `^[A-Z]{1,8}$`. Non-form callers keep the JSON 503. Settings maps the code to fixed text (`SERVER_NOT_CONFIGURED`); unknown codes show nothing; shown only to connect roles. Origin notice: "You're on <host>. Open <app host> to connect accounts." from the request host vs `NEXT_PUBLIC_APP_URL`, hosts validated as plain `host[:port]`, shown only to users who see a connect section.
