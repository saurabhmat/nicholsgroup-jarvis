# T-030 Connector contract

## Summary
The provider-agnostic connector contract (architecture §6 M2) as Zod schemas + TypeScript interfaces, a reusable contract
test kit every connector must pass, and an in-memory mock connector (synthetic data only) that passes the kit.
No provider code, no network calls, no SQL.

- **Schemas** (`@nichols/connectors`): `Provider`, `ConnectionStatus` (`pending | active | degraded | reconnect_required | disconnected`),
  `Connection` (strict object: token/secret fields are rejected), `ConnectionFeatures` (edition flags such as `class_tracking`, QB-10),
  `ConnectInput` (in-app OAuth code only, https redirect, PKCE verifier, callback account id, reconnect connection id),
  `ReadOp`, `SourceResult` (`as_of`, `fetched_at`, `freshness: live|cached|stale`, `provider_tid`, source refs),
  `RawRecord` (mirrors `raw.source_records`, T-039), `SyncCursor`, `SyncSummary` (`full|incremental`), `HealthStatus`,
  `Subscription`, `WriteIntent`, `ProposedPayload` (no hash/approval fields), `ExecResult`, `ConnectorErrorInfo`
  (`http_status`, `provider_error_code`, `provider_tid` = Intuit `intuit_tid`, `retry_after_seconds`, endpoint template).
  Data shapes are snake_case because they mirror stored rows (T-031, T-039, T-196, T-110); function params are camelCase.
- **`Connector` interface**: every method takes `laneId` first. `connect`, `health`, `read` required; `sync`, `subscribe`,
  `prepareWrite`, `disconnect` optional, with `capabilities` flags that must match, plus `readOps` and `featureKeys`.
  Read-only connectors (QuickBooks, Stripe) omit `prepareWrite`.
- **No `executeWrite` on `Connector`.** The write side is `ConnectorWriter<TAction>` in a separate subpath
  `@nichols/connectors/writer` (not re-exported from the root), generic over the approved-action type so T-193 can plug in
  the `ApprovedAction` brand and lint-restrict the subpath to `packages/modules/approvals` (approvals spec §1, §5).
- **`ConnectorError`**: kind → disposition (`retry` for transient/429/timeout, `reconnect_required` never retried, `fail` otherwise;
  QB-3/4/14). No `cause`; `toJSON()` returns the safe info only.
- **Guards**: `assertConnectionUsable(laneId, conn)` (lane mismatch, `reconnect_required`, unusable statuses),
  `assertConnectionInLane`, `isSyncAllowed(status)`, `freshnessOf({asOf, servedFromCache, now, staleAfterSeconds})`
  (thresholds passed in from lane_config).
- **Contract kit** (`@nichols/connectors/testing`): `describeConnectorContract({name, setup})` registers 17 checks;
  `contractChecks` is exported so the kit's own tests prove it catches broken connectors. Checks: no `executeWrite` on the
  surface; capabilities match methods; known provider and well-formed op/feature names; connect returns an active connection
  in the caller's lane; empty laneId rejected; health shape and declared features; cross-lane denial on health/read/sync/
  subscribe/prepareWrite/disconnect; `reconnect_required` refused with a never-retry error and `disconnected` refused;
  SourceResult shape incl. `as_of <= fetched_at`; unsupported/malformed ops throw `ConnectorError`; sync yields valid
  RawRecords in the right lane and returns a cursor that resumes; subscribe shape; prepareWrite returns a ProposedPayload
  and makes zero provider writes; disconnect returns `disconnected`. **Every output and error is scanned for the harness's
  secret canaries.**
- **Mock connector** (`createMockConnector`, `mockHarness`): configurable read-only / no-sync / no-subscribe shapes; counts
  external writes (for T-113's counting executor tests later).

## Tests
- `@nichols/connectors`: 84 passed, 5 skipped (89). The skips are the kit's sync/subscribe/prepareWrite checks on the
  read-only mock variant, which has none of those methods (expected).
  - schema tests (strict Connection rejects `access_token`/`refresh_token`, `reconnect_required` status, `as_of` required,
    freshness enum, JSON-only params, redirect URI https rule, ProposedPayload rejects `payload_sha256`)
  - error tests (dispositions, `invalid_grant`-style never retried, toJSON has no stack/cause, message truncation)
  - guard tests (lane mismatch, empty laneId, status refusal, freshness labels)
  - full kit against two mock shapes; 11 negative tests, each asserting the specific failure reason
    (exposed executeWrite, wrong capabilities, ignored laneId, reading through reconnect_required, bad as_of, plain Error,
    secret in connection, secret in error message, wrong-lane sync records, executing prepareWrite, undeclared feature)
- `pnpm typecheck && pnpm lint && pnpm test` all pass from the repo root.

## Security review
Self-review done (no reviewer subagents spawned by the builder; the orchestrator runs the formal security + code reviews).
- Tokens cannot travel on `Connection` (strict schema) and are never method parameters or return values; the Vault read is
  inside each connector (T-033).
- `ConnectorError` drops `cause` so provider responses/transport errors with tokens or personal data can't leak through logs or
  Sentry; the kit's canary scan covers outputs and error messages.
- No `executeWrite` on the read surface; prepareWrite is kit-checked not to call the provider.

## Risks / deviations
- **`sync` returns an `AsyncGenerator<RawRecord, SyncSummary>`** instead of a bare `AsyncIterable<RawRecord>`: the next cursor
  comes back only when the run completes, so T-038/T-051 persist it only after success. A plain `for await` discards the
  return value; consumers must call `next()` until `done` (the kit's `drain` shows the pattern).
- **Signatures add `laneId`** to every method (architecture shows `read(conn, op)` etc.), per the standing rule.
- **`executeWrite` moved off `Connector`** to `ConnectorWriter` (subpath `./writer`). Until T-193 lands, nothing stops an import of
  that subpath outside approvals except review; the type is generic, so T-193 only has to pass its brand.
- `disconnect?` was added (not in the architecture snippet) for QB-8/T-195.
- `Provider` enum includes a test-only `mock` value; T-031's `core.connections.provider` check should exclude it in production
  data (or accept it only in seed/test).
- Freshness thresholds are a parameter of `freshnessOf`; the lane_config keys for them are not defined yet (T-011/T-081).
- `ConnectInput` has only the `oauth_code` variant; Stripe's restricted key (T-054) will need a Vault-reference variant.
