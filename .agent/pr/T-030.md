# T-030 Connector contract

## Summary
The provider-agnostic connector contract (architecture §6 M2) as Zod schemas + TypeScript interfaces, a reusable contract
test kit every connector must pass, and an in-memory mock connector (synthetic data only) that passes the kit.
No provider code, no network calls, no SQL. Updated after the formal security + code reviews (see "Review").

- **Schemas** (`@nichols/connectors`): `Provider` (real providers only), `ConnectionStatus`
  (`pending | active | degraded | reconnect_required | disconnected`), `Connection` (strict: token fields rejected),
  `ConnectionFeatures` (edition flags such as `class_tracking`, QB-10), `ConnectInput` (`oauth_code` from the in-app
  callback, or `vault_secret` = a reference to a secret already in the Vault, never the secret), `ReadOp`, `SourceResult`
  (`as_of`, `fetched_at`, `freshness: live|cached|stale`, `provider_tid`, source refs), `RawRecord` (mirrors
  `raw.source_records`, T-039), `SyncCursor`, `SyncOptions` (`objectTypes`), `SyncSummary`, `HealthStatus`,
  `Subscription`, `WriteIntent`, `ProposedPayload` (no hash/approval fields), `ExecResult`, `ConnectorErrorInfo`
  (`http_status`, `provider_error_code`, `provider_tid` = Intuit `intuit_tid`, `retry_after_seconds`, endpoint template).
  Data shapes are snake_case (they mirror stored rows); function params are camelCase. Provider-naming schemas come from
  `buildProviderSchemas(providerEnum)` so the test kit can add the test-only provider without touching `ProviderSchema`.
- **Lane-bound connections**: connectors accept only a frozen, branded `LaneBoundConnection` minted by a `ConnectionLoader`
  (`loadConnection(laneId, connectionId)`; real one in T-031/T-016/T-033) or by the connector's own `connect`/`disconnect`.
  Minted objects are tracked in a module-private WeakSet; `assertLaneBound(laneId, conn)` rejects forged or copied objects
  even when `lane_id` matches. `mintLaneBoundConnection` is only on the `@nichols/connectors/internal` subpath.
- **`Connector` interface**: every method takes `laneId` first, then a `LaneBoundConnection`. Connectors re-read the
  authoritative row (lane, status) and their token by `(laneId, connectionId)` on every call. `connect`, `health`, `read`,
  `disconnect` required; `sync`, `subscribe`, `prepareWrite` optional (with matching `capabilities`), plus `readOps`
  and `featureKeys`. `sync(laneId, conn, cursor, sink, options?)` hands records to `sink` in batches and resolves with the
  `SyncSummary` (cursor) only after the whole run succeeded. Read-only connectors omit `prepareWrite`.
- **No `executeWrite` on `Connector`.** The write side is `ConnectorWriter<TAction>` in the `@nichols/connectors/writer`
  subpath (not re-exported from the root), generic over the approved-action type for T-193's brand.
- **`ConnectorError`**: kind → disposition (`retry` / `reconnect_required` never retried / `fail`); no `cause`,
  non-extensible, `toJSON()` = info only. `toConnectorError(unknown)` turns anything else into `provider_error` with a
  generic message.
- **Guards**: `assertStatusUsable(status)` (call with the authoritative status), `isSyncAllowed`, `freshnessOf`.
- **Contract kit** (`@nichols/connectors/testing`): `describeConnectorContract({name, setup})` runs 20 checks;
  `contractChecks` + `runContractCheck` are exported so the kit's own tests prove it catches broken connectors.
- **Mock connector** (`createMockConnector` → `{connector, loader, externalWriteCount, markReconnectRequired,
  simulateInvalidGrant}`, `mockHarness`): authoritative in-memory store, tokens keyed by lane + id, test-only `faults`
  to prove the kit catches cross-lane reconnects, trusting caller status, and executing `prepareWrite`.

## Review
Formal security + code reviews ran on the first commit; all findings below are fixed in `T-030: review fixes`.

**Security**
- **H1 lane binding by convention only** → `LaneBoundConnection` (frozen, branded, WeakSet-tracked) minted only by a
  loader / the connector; `assertLaneBound` rejects forged and copied objects; mint on `./internal` only. Mock re-reads
  lane + status from its store on every call; tokens keyed by (lane, id). `connect` with `reconnect_connection_id` checks
  same lane (else `not_found`), same provider and same account (else `invalid_input`). Contract docs state T-033's
  `getToken` is keyed by `(laneId, connectionId)` and checks `core.connections.lane_id`. Kit: forged other-lane object,
  unminted exact copy, loader cross-lane hiding, cross-lane reconnect (and the original still works).
- **M1 status from the caller's object** → status comes from the authoritative row. Kit hooks: required
  `markReconnectRequired(conn)` (stale `active` object must then fail with the never-retry error); optional
  `simulateInvalidGrant(conn)` (read must raise `reconnect_required`, health then reports it; skipped when absent).
- **M2 error leakage** → `ConnectorError` non-extensible (a `cause` cannot be attached); kit scans `util.inspect(err,
  {depth: Infinity, showHidden: true})`, stack, JSON and the cause chain, and asserts `cause === undefined`, exact
  prototype, non-extensible, own keys ⊆ {name, info, message, stack}. `toConnectorError(unknown)` added.
  *Interpretation:* own keys also allow `message` and `stack`, which `Error` itself creates; both are covered by the
  canary scan.
- **M3 write counting** → `externalWriteCount` required; `runContractCheck` asserts no external writes in any check beyond
  the revocations from that check's own `disconnect` calls; connector objects with unknown function-valued keys fail.
- **M4 mock provider in the real enum** → `ProviderSchema` holds real providers only; `TestProviderSchema` /
  `testSchemas` live in `testing/`; T-031 acceptance updated.
- **L1** redirect URI rejects userinfo and fragments; http only for loopback (`localhost`, `127.0.0.1`, `[::1]`);
  documented that connectors must send the server-configured redirect URI with exact match.
- **L2** writer docs: `executeWrite` asserts `action.lane_id === laneId` and `action.connection_id === conn.id`.
- **L3** `endpoint` must be a path template without query/fragment; docs say message redaction is T-033's job.
- **L4** kit matches raw, base64, base64url and URL-encoded canary forms.
- **L5** `zod` pinned exactly `4.6.7`.

**Code review**
1. Redirect refine threw a `TypeError` on non-URLs → `URL.canParse` first; test added.
2. Writer docs point to `docs/specs/approvals.md` §4 for the hash (SHA-256 over RFC 8785 canonical JSON of
   `{lane_id, action_type, connection_id, target, payload, payload_schema_version}`).
3. `ConnectInput` `vault_secret` variant (`secret_ref` uuid + `external_account_id`, optional `reconnect_connection_id`).
- Decided changes applied: sink-based `sync` returning the parsed `SyncSummary`; `disconnect` required (capability flag
  removed); kit checks health on `reconnect_required`/disconnected returns `ok: false` without throwing and reuses one
  guard helper (`expectGuarded`) for read/sync/subscribe/prepareWrite; vitest dev + optional peer dependency; T-062
  wording updated.

## Remaining risks
- `./internal` (mint) and `./writer` (`executeWrite`) are restricted by convention until the boundary lint rules land
  (T-003 / T-193). Any package can import them today.
- The WeakSet brand is per module instance. If a bundler ever loads `contract/lane-bound.ts` twice, connections minted in
  one copy fail `assertLaneBound` in the other. That fails closed, but would look like a bug.
- The brand stops forged objects in-process only. Lane safety for real data still depends on T-031 RLS, the T-016 lane
  router and T-033's `(laneId, connectionId)`-keyed `getToken`.
- The kit checks only what a harness exposes: a real connector's `markReconnectRequired`/`externalWriteCount` hooks must
  be wired to its MSW handlers and store, or the M1/M3 checks lose their teeth.
- Freshness thresholds are a `freshnessOf` parameter; their lane_config keys are not defined yet (T-011/T-081).
