# T-016: Lane router

## Changes
- `@nichols/core/lane-router` (`packages/core/src/lane-router/index.ts`, starts with `import "server-only"`; a test reads the source and checks it):
  - `getLaneClient(laneId, session)`: a supabase-js client acting as the user (publishable key + the user's access token), so RLS applies to every query. Before returning it, the router reads the lane row with that token (`core.lanes` where code = lane and enabled): RLS returns it only to an AAL2 member of an enabled lane. No row, error or missing session → `LaneAccessError("not_allowed")`.
  - `getLaneJobClient(laneId)`: the service client (secret key, singleton) for jobs; the lane must be enabled in the database.
  - Both refuse a malformed lane id and a lane missing from `ENABLED_LANES` before any query.
  - Data-plane registry: `core` = this project; the `nl` slot is defined and fails closed (`data_plane_unavailable`) until the NL project exists.
  - `getAudit()`: the T-015 audit API wired to `audit.log()` through the service client.
  - `createLaneRouter(factory)` for tests (client factory injected).
- `supabase/core/supabase/config.toml`: API exposes `core` and `audit` (server code reaches them through supabase-js). RLS, grants and the catalog test govern what anyone can see; anon has nothing.
- `pnpm db:types` now types `public`, `core` and `audit`.
- Dependencies: `@supabase/supabase-js` 2.118.0 (pinned) in `@nichols/core`, importable only from the lane router (T-003 lint); dependency allowlist updated. The allowlist test now lets a package declare a vendor SDK when it contains a permitted path (the lint rule still restricts the import to that path).

## Tests
- `lane-router.test.ts` (11) with a fake client factory: server-only first line; user client built from the session token; lane query filters code and enabled; non-member/disabled/AAL1 (no row), query errors and missing sessions refused; malformed and unserved lanes refused before any query; NL fails closed; job client uses the service client; audit rows go to `audit.log` and rpc errors become AuditError without the database message.
- The RLS behaviour the router relies on is proven in pgTAP (020, 030).
