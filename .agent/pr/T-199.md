# T-199: Settings → Connections page with the Google connection

## Summary
A Google section on the lane's Settings page for owner and admin_technical at AAL2. It shows each connected mailbox, its status and the last mail and calendar sync times ("not synced yet" when none), and has a Connect / Reconnect button that starts the existing T-063 flow. When a connection is `reconnect_required` it shows a banner. There is no Disconnect button (D-24); the page explains how to remove access at Google. No SQL change, no new route, no external write.

## Changes
- `apps/web/lib/google-connection.ts`
  - `loadGoogleSection(client, laneId)` reads through the signed-in user's own lane client, under RLS with AAL2 and the role views. It reads:
    - `core.connections`: id, mailbox and status; Google only, this lane only.
    - `core.sync_cursors`: `updated_at` for the `mail` and `calendar` streams. `cursor_value` is never selected (it is not granted anyway).
    - `lane_config_current`: only `config->mailboxes`. The mailbox check ignores case, the same as the connector guard.
  - `disconnected` rows are hidden.
  - `googleSectionFor(guards, laneId)` decides who sees the section and what happens on errors:
    - It uses `requireRole(lane, CONNECT_ROLES)` and returns null for any `AuthError`.
    - An outage in the role check is rethrown.
    - A database error while reading gives an `unavailable` view, so the page never shows "not connected" for an outage and the rest of Settings still renders.
- `apps/web/components/google-connection-section.tsx`: a server component inside a `<section>` labelled "Google".
  - The button is a same-origin form POST to `/api/connect/google/start?lane=<lane>`. That route is POST-only, checks the Origin header, and checks role and AAL2 again itself.
  - Button labels: "Connect Google", "Reconnect Google" (with the banner), or "Connect another Google account".
  - The wording says this connects mail, calendar and Drive read-only and is not how anyone signs in.
  - The page shows no message subjects, senders or event titles.
- `apps/web/components/settings-page.tsx`: renders the section after the `loadLane` gate.
- `apps/web/scripts/e2e-sql.mjs` (+ `.d.mts`): runs fixed synthetic SQL in the local Supabase DB container through `docker exec psql`. It passes arguments directly with no shell, and the SQL goes in on stdin. The e2e lint rule forbids `child_process` inside `e2e/`, so this helper lives in `scripts/`.

## Tests
- `apps/web/tests/google-connection.test.ts` (20):
  - status mapping;
  - the output shape (extra token or cursor columns are not passed through);
  - every read is filtered by lane, provider and stream;
  - only `mailboxes` is read from lane config;
  - several connections, with sync times matched per connection and per stream;
  - "not synced yet" and a mailbox outside the lane's list;
  - `reconnect_required`, with `disconnected` rows hidden;
  - no connection means no further reads;
  - a database error throws;
  - the exact roles asked for; forbidden, no session and MFA required give no section and no read;
  - an outage in the role check is rethrown; an outage while reading gives the unavailable view.
- `apps/web/e2e/settings-google.spec.ts`. The spec seeds and removes only its own synthetic connection (fixed id), and stops instead of deleting if a real local Google connection exists in PKG.
  - Owner (desktop) goes through four states:
    - Not connected: the form posts to `/api/connect/google/start?lane=PKG`; no Disconnect button; the remove-access help is shown.
    - Connected, not synced yet.
    - Synced: the times are shown in ET; the cursor value never appears.
    - `reconnect_required`: the banner and the Reconnect button appear.
  - Viewer (desktop) and finance operator (iphone): with a connection seeded, they see no section, no Google buttons and no mailbox or sync details.
  - admin_technical (iphone) sees the section.
  - Connect is not clicked, because that would leave for Google. The start and callback flow is covered by the connector tests with the MSW Google mocks (`packages/connectors/src/oauth/flow.test.ts`, `apps/web/tests/connect-authorizer.test.ts`).
- Covered by existing tests:
  - Other lanes get a 404 from `loadLane` (`e2e/shell.spec.ts`).
  - The start route returns 403 for other roles and AAL1 (`connect-authorizer.test.ts`, `oauth/flow.test.ts`).
- Results:
  - `pnpm typecheck && pnpm lint && pnpm test`: all 17 packages pass (web 102 tests).
  - Playwright `settings-google.spec.ts`: 4 passed, 2 skipped by design (each persona exists on one project only).
  - No SQL changed, so `pnpm test:db` is not required.

## Risks and needs a human
- "Last sync" is when the sync last saved data. A run that finds nothing new does not move it, so a quiet mailbox can look stale. This is logged; fixing it needs a per-stream "last successful run" time that these roles can read.
- **H-032** (manual live check with a sandbox Google account) is still open.
- No new environment variable.
