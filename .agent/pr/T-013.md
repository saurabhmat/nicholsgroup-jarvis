# T-013: RLS conventions and catalog test

## Changes
- `supabase/core/supabase/tests/050_catalog.test.sql`: fails when, in any app schema (every schema except the platform list, so new schemas are covered automatically):
  - a table lacks `lane_id`, RLS or a policy;
  - a SELECT policy does not require aal2 and go through `core.allowed_lanes`, or a lane table deviates from the standard policy shape;
  - a policy applies to public/anon, anon has any privilege, or authenticated has direct DML;
  - a view is not `security_invoker`;
  - a function does not pin an empty `search_path`, or anon can execute it.
  Exceptions are reviewed lists with a reason per entry (`core.lanes`, `core.users` without `lane_id`; `core.lanes`, `core.users`, `core.memberships` with custom policies); stale entries fail.
- `supabase/core/supabase/tests/helpers/lane_rls.psql`: shared helpers (`pg_temp.claims`, `uid`, `lanes_for`, `has_standard_lane_policy`); 020/030/040 now include it instead of redefining them.
- `supabase/core/templates/lane_table.sql`: migration template with the standard policy, grants and test checklist.
- `supabase/core/README.md`: the lane conventions.

## Tests
- `pnpm test:db`: 6 files pass. The catalog test was checked against a planted bad schema (table without lane_id/RLS/policy and with an anon grant, a definer view, a function without search_path): 7 of its 13 assertions failed, naming each object.

## Review (security, Oct 31, 2026; one HIGH, fixed)
- H1, M1 (fixed): the policy check matched fragments, so a policy that OR-ed in every row, or hard-coded a lane list, passed. Lane tables must now have exactly one permissive policy: SELECT, for authenticated only, whose whole expression equals the canonical text (`pg_temp.standard_lane_qual(view)`) for a view in `core.view_names()`. Custom policies are a reviewed list and must still start with the aal2 conjunct.
- M2 (fixed): column-level grants (`has_any_column_privilege`) and write/ALL policies are checked.
- M3 (fixed): materialized views and foreign tables readable by authenticated fail (they bypass RLS).
- M4 (fixed): security-definer functions and functions executable by authenticated must be on reviewed lists (`security_definer_ok`, `authenticated_exec_ok`).
- M5 (fixed): `has_standard_lane_policy` uses the same exact-match rule and column grants.
- L4 (fixed): relations in `extensions` not owned by supabase_admin fail. L5 (fixed): sequence privileges for anon/authenticated fail; the template revokes them. L6 (fixed): `security_invoker=on/1/yes` accepted.
- Verified: a probe copy planting each reviewer exploit (leaky role-claim policy, hard-coded lanes, column insert grant + insert policy, materialized view over audit.events, unreviewed definer function, sequence grant) failed 9 of 20 assertions, naming every object.
