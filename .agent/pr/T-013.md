# T-013: RLS conventions and catalog test

## Changes
- `supabase/core/supabase/tests/050_catalog.test.sql`: fails when, in any app schema (every schema except the platform list, so new schemas are covered automatically):
  - a table lacks `lane_id`, RLS or a policy;
  - a SELECT policy does not require aal2 and go through `core.allowed_lanes`, or a lane table deviates from the standard policy shape;
  - a policy applies to public/anon, anon has any privilege, or authenticated has direct DML;
  - a view is not `security_invoker`;
  - a function does not pin an empty `search_path`, or anon can execute it.
  Exceptions are reviewed lists with a reason per entry (`core.lanes`, `core.users` without `lane_id`; `core.lanes`, `core.users`, `core.memberships` with custom policies); stale entries fail.
- `supabase/core/supabase/tests/helpers/lane_rls.psql`: shared helpers (`pg_temp.claims`, `uid`, `lanes_for`, `has_standard_lane_policy`); 020/030/040 now include it instead of redefining them.
- `supabase/core/templates/lane_table.sql`: migration template with the standard policy, grants and test checklist.
- `supabase/core/README.md`: the lane conventions.
