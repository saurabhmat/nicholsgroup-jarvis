## How message content is rendered (the exact rule)
Server-side conversion to typed nodes; React draws nodes as text. **No `dangerouslySetInnerHTML`, no HTML string reaches the browser** (a source test pins it). Allow-list of node kinds: text, line break, paragraph (p, div, headings: headings become bold), bold, italic, underline, strike, inline code, code block, quote, bullet / numbered list with items, link, mention, emoji, image placeholder; table cells are flattened to text. Dropped with their content: script, style, iframe, frame(set), object, embed, applet, noscript, template, svg, math, title, head, audio, video, canvas, select, textarea, button, form, xmp, plaintext, noembed, noframes, link, meta, base; comments, CDATA, doctype and processing instructions are skipped. Unknown tags keep their text only. Attributes read: a link's `href`, an emoji's `alt`, an image's `src` and `itemtype` (never kept as an address). Links: written `https://` only, no credentials, at most 2,048 characters, no whitespace / control / bidi character, the URL parser's normalised `href` is what is checked AND drawn, shown with its real host (punycode for look-alikes), `target="_blank" rel="noopener noreferrer nofollow"`, never fetched or auto-opened; nested links keep only the outer. Images: only `graph.microsoft.com/.../hostedContents/...` becomes a neutral placeholder ("Image: open the chat in Teams to see it"); every other image (trackers, remote pictures, `data:`) is dropped and nothing is loaded. Mentions `<at>` become "@Name" text (markup in a mention is ignored, a name that looks like markup stays text). Emoji: `<emoji alt>` and `<img itemtype=...Emoji alt>` become their alt text (at most 16 characters). Text: bidi overrides/isolates/marks, zero-width space, word joiner, BOM, soft hyphen and C0/C1 controls removed (joiners kept for emoji); `dir="auto"` on names and bodies; entities decoded once (no double decode); at most 20,000 characters, 5,000 nodes, nesting 12, input bounded to 160,000 characters before any work, the cut is reported ("This message is long; open the chat in Teams ...") never silent. Plain-text bodies and unknown content types are text (lines become breaks). Deleted messages and system events show no body at all (the text is not even converted). Attachments: stub with a name (text) and, for a file with an https `contentUrl`, an "Open (Opens in Microsoft)" link (never fetched); cards, replies (`messageReference`: "Replied to an earlier message", content not parsed) and others are labelled "open in Teams". A second look in `renderNodes`: a link node whose href is not https is drawn as text.
