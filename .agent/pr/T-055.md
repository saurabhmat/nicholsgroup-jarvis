# T-055 Finance normalized schema, part 1 (ledger and reports)

## Summary
New schema `fin` with six lane-scoped tables, RLS on the standard `finance` lane policy, service_role-only writes, composite foreign keys that tie each row to a QuickBooks connection of the same lane and to its raw source record, and pgTAP (`130_fin_ledger_and_reports.test.sql`, 213 tests). Migration `20261104120000_fin_ledger_and_reports.sql`. `scripts/gen-db-types.mjs` now also generates the `fin` schema; `packages/core/src/db/types.ts` regenerated.

## Tables and columns
Common to all six: `id uuid`, `lane_id` (FK core.lanes), `connection_id`, `provider` (check = 'quickbooks'), `raw_record_id` (nullable, FK to raw.source_records, `on delete set null`), `source_updated_at timestamptz`, `created_at`, `updated_at`. Composite FKs: `(connection_id, lane_id, provider) -> core.connections`, `(raw_record_id, connection_id) -> raw.source_records`.
- `fin.accounts`: `source_id`, `name`, `type`, `subtype`, `is_bank`, `entity_code`, `owner_entity_code`, `active`. No balance, no account/routing numbers. Unique `(connection_id, source_id)`.
- `fin.transactions`: `source_id`, `txn_type`, `line_no`, `txn_date date`, `posted_at timestamptz`, `account_id` (FK, same connection), `class_id`, `entity_code`, `amount numeric(18,2)`, `is_uncategorized`, `voided`, `deleted`. Unique `(connection_id, txn_type, source_id, line_no)`.
- `fin.invoices`: `source_id`, `customer_id`, `issue_date`, `due_date`, `total`, `balance` (numeric(18,2)), `class_id`, `entity_code`, `voided`, `deleted`.
- `fin.payments`: `source_id`, `invoice_id` (nullable FK), `paid_at timestamptz`, `amount`, `entity_code`, `voided`, `deleted`. One row per (payment, invoice allocation).
- `fin.bills`: as invoices with `vendor_id`.
- `fin.report_cache`: `report`, `params jsonb`, `params_hash` (set by trigger), `payload jsonb`, `as_of`, `fetched_at`. Unique `(lane_id, connection_id, report, params_hash, as_of)`.
Identity columns (lane, connection, provider, source id, type, line, report, as_of) are frozen by a trigger (42501).

The catalog test (050) passes unchanged.

## Decisions and deviations (spec silent or extended)
1. Extra columns: `connection_id`, `provider`, `raw_record_id`, `source_updated_at`, `deleted`, `line_no`. Reason: a lane can hold several QBO files (D-8), QBO ids are per entity type, deleted records must stay as rows for audit (views exclude them), T-039 raw refs.
2. `report_cache` unique key includes `connection_id`.
3. `fin.payments` is one row per invoice allocation; `invoice_id` nullable for unapplied payments. BillPayment not modelled.
4. `fin.transactions` is one row per posting line; `account_id` and `class_id` optional (fail soft); sign convention left to T-056.
5. `entity_code` shape check only; the code list stays in lane_config (rule 2).
6. Added unique indexes on `core.connections (id, lane_id, provider)` and `raw.source_records (id, connection_id)` to carry the composite FKs.
7. `fin` is NOT added to PostgREST `api.schemas` (T-081 decides); types are generated.
8. Viewers with the named `finance` view read everything in these tables, per spec §5.

## Risks
- No DB-side forbidden-key guard on `report_cache.payload`; relies on connector projection (logged in plan-review §6).
- Purging raw rows nulls `raw_record_id` through the FK; fine for the normalizer, but lineage is lost then.
- The db-engineer, security-reviewer and code-reviewer passes were not run by the builder.
