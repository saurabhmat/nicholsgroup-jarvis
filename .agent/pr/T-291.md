### T-285 inline images
- `GET /api/lanes/<lane>/messages/image?chat=<key>&message=<id>&hosted=<id>` (or `?team=<id>&channel=<key>&message=<id>&hosted=<id>`): `apps/web/app/api/lanes/[laneId]/messages/image/route.ts`, logic in `apps/web/lib/teams-api.ts` (`image`).
  - Checks, in order: same site (`Sec-Fetch-Site` absent or `same-origin`) -> lane id shape -> AAL2 session in the lane with `own_mail` (owner, admin_technical, viewer) -> the `messages` module is shown -> the person's OWN usable Teams connection (read under RLS; the route takes no connection id) -> strict address (each of the five parameters at most once, no other parameter, `message` and `hosted` match the connector's id format and are not a dot segment, a chat key or team + channel key that decodes to a valid id, never both) -> the connection has `chat_read` (chat) or `channels_read` (channel) -> the connector: guard (owner = signed-in user, lane, tenant, domain, lane feature AND connection feature) -> fixed template -> bytes.
  - Bytes: `responseType: "bytes"` (new in the shared HTTP client), cap 4 MiB + 64 KiB enforced WHILE streaming (declared length checked first), no retry, 15 s timeout, 1 request/s per chat (own bucket) or per channel.
  - Type decided by the server from the first bytes (PNG, JPEG, GIF87a/89a, WebP); Microsoft's `Content-Type` is never read or echoed; SVG, HTML and everything else -> 415; over the cap -> 413.
  - Response headers: `Content-Type` (the sniffed one), `X-Content-Type-Options: nosniff`, `Content-Disposition: inline; filename="image"`, `Cache-Control: private, no-store`, `Content-Security-Policy: default-src 'none'; sandbox`, `Cross-Origin-Resource-Policy: same-origin`, `Referrer-Policy: no-referrer`, `Content-Length`.
  - Failures are fixed JSON (400, 403, 404, 409, 413, 415, 429 + `Retry-After`, 503), `no-store`; nothing from Microsoft or the request is in them. The only log line is the existing `[api/teams-messages] unavailable: <error class>`.
  - Nothing is stored or cached; the route file exports GET only.
- Converter (`packages/connectors/src/teams/message-html.ts`, new `hosted-content.ts`): an `image` node carries `hosted: <id>` ONLY when the `<img src>` is exactly `https://graph.microsoft.com/v1.0/chats/<chat>/messages/<message>/hostedContents/<id>/$value` (or the `teams/<team>/channels/<channel>/messages/<message>/...` form) AND the chat/team/channel/message in it equal those of the message being converted. No scheme other than https, no other host or port, no user name, query, fragment, extra or encoded-slash segment. The address itself is dropped. Previews, replies and unknown shapes stay plain placeholders.
- Page: `messages-image.tsx` (client): `<img>` to the same-origin route, fixed `alt="Image"`, `loading="lazy"`, `referrerPolicy="no-referrer"`, a fixed 16 x 12 rem box (`max-w-full`), click opens the same route in a new tab; any error event, an id that does not validate, or a source that is not `/api/lanes/<LANE>/messages/image?...` draws the neutral placeholder. A picture inside a link is a placeholder.

## How each channel state is decided
(`apps/web/lib/teams-messages.ts` `channelsAvailability`, from the connect state; no Microsoft request is made for any state except "ready")
1. Company's `teams.features` lacks `channels_read` -> "Channels are not switched on for this company." (neutral, no button, no error).
2. Company lists it, connection's `teams_channels_read` is false (connected before, or the admin consent was not given when it connected) -> "Reconnect Teams to add channels" + the administrator-approval text + Reconnect button. The old page-level note leaves channels out while the Channels tab is open (no duplicate).
3. Ready: teams are read. A refused team list (403) -> "Channels need your Microsoft administrator's approval" + admin text (no retry button). A refused channel (403) -> "A private channel can be read only by its members". 429 -> "Teams is busy, try again in N seconds". 401 refresh failure -> Reconnect Teams. Others -> "could not read your teams", Try again.
The guard enforces the same at the connector: lane feature AND connection feature, so a token without the channel scopes never reaches a channel endpoint (tested: no token read, no request). Chats are unaffected in every state.
