## Decisions
See docs/plan-review.md "T-064 design notes". Short: encoded calendar id (`#` -> `=23`), `primary` alias, conservative default selection (D-26, lane_config-driven), 410 = whole-connection resync, `showDeleted=true` on full loads, deletions as cancelled stubs (`removedEventsAreStubs` in the contract harness), forward-horizon reload at half, `readBody` limited to synced calendars, fields mask without description.

## Live check (human present, Saurabh's own account; do not do this unattended; extends the T-063 one, H-033)
Prerequisite: the T-063 live check (H-032) is done: a Google connection for your mailbox exists, `active`, and PKG `lane_config.mailboxes` lists it. Nothing here touches staging or production.
1. Optionally set `lane_config.calendar` for PKG (local DB only). Default: primary + your owned/writable calendars that are ticked in Google Calendar. To include the US holiday calendar: `{"calendar": {"include_read_only": true}}` (its id contains `#`; it will be stored as `en.usa=23holiday@group.v.calendar.google.com`).
2. Run one sync from a scratch script (server-side, `APP_ENV=local` env loaded): `calSync.run("PKG", await connectionLoader.loadConnection("PKG", "<connection id>"))` from `@nichols/connectors/google`.
3. Check: `select calendar_id, count(*), min(start_at), max(start_at), count(*) filter (where status='cancelled') from cal.event_index group by 1;` shows only the calendars you expect (`primary` for your own); `select cursor_value from core.sync_cursors where stream='calendar';` starts with `g1.<connection id>.c:`; `last_sync_at` is set; no column holds a description.
4. DST / all-day: pick an all-day event, `select start_date, end_date, start_at, end_at, timezone from cal.event_index where all_day limit 5;` end_date is the day AFTER the last day; start_at is local midnight of start_date in the calendar's zone.
5. Recurring: a weekly meeting appears as separate rows with `recurring_event_id` set and `original_start_at`.
6. Incremental: run again (few or zero writes). In Google Calendar create an event, move one, delete one, run again: the new event appears, the moved one updates, the deleted one has `status = 'cancelled'` with its title kept.
7. Live description: `googleCalendarProvider.readBody("PKG", conn, "primary", "<event id>")` returns an UntrustedBody; confirm nothing was written (`select count(*) from cal.event_index` unchanged) and the logs hold no description text.
8. Reset: in Google remove the app (https://myaccount.google.com/permissions); locally `supabase db reset --local --workdir supabase/core`.
