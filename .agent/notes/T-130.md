## Built (no SQL)
- `cal-ingest-delta` Inngest cron `*/15 * * * *` (packages/core/src/inngest/cal-ingest.ts). Per enabled lane lists usable
  (active/degraded) connections of calendar providers (google) via the lane job client (connectors/sync/targets.ts), sends
  conn/sync.requested trigger "schedule", event id `cal-ingest:<connectionId>:<slot>` (slot = floor(cron ts / 15 min)).
- 15 min: a moved meeting shows within a quarter hour; an unchanged delta is one cheap request per calendar; quota is far away.
- Lane listing failure is isolated per lane; healthy lanes are sent first, then the run fails (NonRetriable) so it is visible; next tick retries.
- conn.sync: `trigger` now required in the event schema; `singleton {key: connectionId, mode: skip}` added (T-038 note).
- No `streams` option: conn.sync running mail too is cheap and a split adds event fields/run-log semantics for no gain.
- Duration/stale (T-038 M4): maxDuration can only be set as route segment config, forbidden under cacheComponents. Not changed; logged.
  Default function duration is far below STALE_RUN_MS (30 min), so a run cannot outlive the stale limit today.
