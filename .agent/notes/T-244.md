# T-244 notes: Finance page and Net income from live QuickBooks data

## Root cause (confirmed)
core.home_finance reads the cached `pnl` whose params.start_date = first day of the current month (America/New_York). planReports fetched the P&L
only for lane_config.finance.reports.period (year to date: start Jan 1, or trailing 12 months). Outside January no row ever matched: cache-key
mismatch, not ET/UTC, not fiscal vs calendar, not connection, not freshness (there is no freshness rule: the newest matching row wins and its as_of is shown).

## Decisions
- Reports job: when `pnl` is in the kinds it also fetches week to date (Saturday..today), month to date and calendar year to date, same end date (today, ET),
  same method and class rules. Windows with the same start are one request (Saturday, the 1st, Jan 1, ytd configured). Extras come after the configured kinds.
- No `period` field in params: the date range is the key, so a request of the same range is the same cached row. (The lead's SQL lists params->>'period'; it shows null. Harmless.)
- Calendar year, not fiscal: no fiscal-year start exists in lane_config or the connection.
- Rate/budget: API_RATE_LIMIT is 450 requests/min per connection; a run makes the Account query pages + up to 5 reports + up to 3 extra P&L = a handful. No per-run budget exists in the job. Extra cost: up to 3 QuickBooks calls per nightly run.
- Nightly cadence (02:00 ET): week and month figures are up to a day old; the card shows the report's as_of and its date range. On the 1st, or on a new Saturday/year, the new window is "not synced yet" until the next run (or a manual event).
- SQL: core.finance_pnl_window (shared extraction, invoker), home_finance now calls it (its month reason stays month_report_not_cached; output columns unchanged), core.finance_pnl(lane, period) week|mtd|ytd (unknown period = 22023), core.finance_overview(lane) (own-entity open AR total = aging sum, open unmapped bills, last normalize, report METADATA only, current connections only).
- AR card = total open own-entity USD invoices from SQL (finance_overview), shown with the aging total; no addition in TS.
- Period toggle: server-rendered links `?period=week|mtd|ytd`, default mtd, unknown values fall back. The client PeriodToggle in @nichols/ui is unchanged (still used nowhere else).
- Controls: connection status, last sync, last normalize, unmapped bank accounts / open invoices / open bills, shared bank accounts. Missing (stated in the page): reconciliation, bank feed health, uncategorised transactions.
- Reports: cached report metadata list. Weekly cash report and month-end snapshots do not exist anywhere yet: always the "not generated yet" line.
- Access: same reads as Home; no_access shows a plain message with no figures and no toggle; during an outage hasFinanceView decides whether the outage line or the no-access message is shown.
- Subscriptions card unchanged.
- Not done: a fiscal-year option, a retention job for report_cache history (growth: 4 P&L rows per night per connection, older rows are never read; plan-review already tracks retention for T-052).
