# T-030 notes — Connector contract

Plan:
- `src/contract/schemas.ts`: Zod schemas + inferred types. Data shapes are snake_case (they mirror DB rows:
  `core.connections` T-031, `raw.source_records` T-039, `connector_api_errors` T-196); function params are camelCase.
  `Provider`, `ConnectionStatus` (incl. `reconnect_required`), `Connection` (strict: no token fields), `ConnectionFeatures`
  (edition flags such as `class_tracking`), `ConnectInput`, `ReadOp`, `SourceResult` (`as_of`, `fetched_at`, `freshness`,
  `provider_tid`), `RawRecord`, `SyncCursor`/`SyncSummary`, `HealthStatus`, `Subscription`, `WriteIntent`,
  `ProposedPayload`, `ExecResult`, `ConnectorErrorInfo`.
- `src/contract/errors.ts`: `ConnectorError` with kind → disposition (`retry | reconnect_required | fail`), `provider_tid`,
  `retry_after_seconds`; no `cause`, `toJSON` = info only.
- `src/contract/guards.ts`: `assertConnectionUsable(laneId, conn)` (lane mismatch + status), `isSyncAllowed`, `freshnessOf`.
- `src/contract/connector.ts`: `Connector` — every method takes `laneId` first. `sync` is an `AsyncGenerator<RawRecord, SyncSummary>`
  (cursor returned only when the run completes). `prepareWrite?` optional. **No `executeWrite`** on `Connector`.
- `src/contract/writer.ts` (subpath `@nichols/connectors/writer`): `ConnectorWriter<TAction>` with `executeWrite`, generic over
  the approved-action type so T-193 plugs in the `ApprovedAction` brand and lint-restricts this subpath to approvals.
- `src/testing` (subpath `@nichols/connectors/testing`): `contractChecks` + `describeConnectorContract(fixture)`, and
  `createMockConnector` used by the kit's own tests (and later T-038/T-113).
- Tests first: schema tests, error tests, guard tests, kit-on-mock, kit-catches-broken-connectors.
