## Plan
1. Converter first (`packages/connectors/src/teams/message-html.ts`): hand-written tokenizer plus allow-list (no sanitiser dependency exists in the repo; mail is shown as plain text). Output is typed nodes, never HTML.
2. Reader (`reader.ts`): strict Zod projections over the phase 1 guarded GET client. `api.get` now hands back the guard's `{tenantId, entraObjectId}` (`self`) and takes `retry: false` (a page request never retries: 429 reaches the page with Retry-After).
3. SQL (T-282): `comms.teams_chat_reads` + definer writer + `core` invoker wrappers (comms is not exposed to PostgREST) + two service_role purges; migration `20261201100000`, pgTAP 329, gitignored production part 34.
4. Web: `lib/teams-chats.ts` (views), `lib/teams-api.ts` (3 small routes), `components/messages-{view,chats,client}.tsx`; page streams two Suspense sections whose reads start together after the gate.
5. T-284: `resolveCallTargets` + `deep-links.ts` + `POST .../messages/call-link` + buttons.
6. S9 from the T-278 review: refresh scope check in the shared token manager (`checkRefreshScope`, Teams passes `assertTeamsGrantedScopes`).

## Decisions made while building
- Route prefix is `/api/lanes/<lane>/messages/...` (the repo's convention) not `/api/<lane>/...` as the spec text says.
- Unread dot of the open chat is dropped server-side while the marker is written from the browser once (`MarkRead` -> `POST .../messages/read`): no write during a GET render.
- "More chats" is a link with an opaque cursor in `?more=`; "Load older messages" is a click that fetches one more page and appends it.
- Chat list time = today the time, last six days the weekday, earlier the date; message times `h:mm a` with ET in the tooltip and a note.
