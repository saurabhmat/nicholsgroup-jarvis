# T-007 notes
- Lane/membership/config tables do not exist yet (T-010/T-011/T-012), so T-007 ships the framework, the data
  definitions and the only seed that can exist today: the five persona auth users.
- Framework lives in `supabase/core/seed/` (architecture §10 puts seeds under `supabase/core/seed/`). Plain ESM `.mjs`
  so it runs on Node 22 with no build step (same reason as `scripts/*.mjs`); tested with `node --test`.
- RNG: SHA-256 counter stream keyed by `seed + label` (node:crypto), so it is stable across Node versions. Each section
  and each persona gets its own derived stream, so adding a section never shifts another section's ids.
- Output: `supabase/core/supabase/seed.sql` (already the `[db.seed] sql_paths` entry). Generated and committed;
  `pnpm db:reset` regenerates then resets locally; a unit test and `test:db` fail on drift.
- Guard runs inside the generator (fails closed) and in tests: emails only on `example.test`, no domain-like
  strings in literals except reserved ones, capitalized words in literals only from the lane names + persona labels,
  and a denylist of known real names/domains anywhere in the file.
- Personas: no password (empty hash), reserved undeliverable domain, so they cannot sign in anywhere but local tests
  (admin API / Mailpit). Roles are not put in auth metadata; memberships are T-012's job (intended ones are data).
