# T-051 QuickBooks entity sync (CDC) - notes

Plan / design
- `quickbooks/entities.ts`: strict Zod allowlist projection per entity (zod objects strip unknown keys at every level). CustomField, AcctNum/BankAccountNum, contact blocks, memos, tax detail never kept. Records that fail the shape throw provider_error (fail closed, cursor stays).
- `quickbooks/sync.ts`: `Connector.sync` for QuickBooks. Preferences + CompanyInfo first (every run), flags -> `quickbooks/features.ts` (diff, audit-before-change via withAudit, update of core.connections.features/features_checked_at). Full load = paged query (STARTPOSITION/MAXRESULTS 1000, `Active in (true,false)` for Account/Class/Customer/Vendor); incremental = one `/cdc` call. Cursor = run start - 5 min (ISO, ms, Z). Stale (>= 30d - 1h), missing, malformed, future -> full. CDC 1000/entity cap -> full. Targeted (objectTypes) needs a fresh cursor and returns it unchanged.
- Runner: `quickbooks: createConnectorSyncRunner(...)` in `sync/index.ts`, cursor in stream 'default' (no SQL change, so no migration / pgTAP / db types).
- Capability `sync: true` (existing tests updated); contract kit runs the sync checks against QuickBooks.
- Fake Intuit extended (preferences, query, cdc, tripwire for any other path) + `testing/msw/quickbooks/fixtures.ts` synthetic data with hazards.

No SQL. Audit uses existing audit.log through getAudit(). Store for features lives in vault/index.ts (job client restricted by lint to the vault folder).
