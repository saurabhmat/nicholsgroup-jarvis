Open-link bug. Home's "Open thread" used `ThreadRow.sourceUrl` = `comms.message_index.source_url`, written by the Gmail sync as
`https://mail.google.com/mail/u/<url-encoded address>/#all/<id>`. Gmail's `/mail/u/<n>/` takes an account INDEX, not an address, so the
address form is not honoured and Google lands on the default account / a different page; it also fell back to the MESSAGE id when the
thread id was missing. Fix: Home never links to a stored provider URL any more. "Open" (and "Open thread" in the drafts/deadlines)
goes to `/<lane>/inbox/<messageId>` (lib/inbox-links.ts). The sync now writes `gmailThreadUrl(mailbox, threadId)`
(packages/connectors/src/comms/gmail-url.ts: `https://mail.google.com/mail/?authuser=<encoded mailbox>#all/<hex thread id>`, null when the
thread id is not `^[0-9a-f]{8,32}$` or the mailbox is not one plain address) and the thread view builds the same URL itself from the
thread id + the connection's mailbox (never from the stored column, so old rows with the bad shape are not used).
