# T-038 conn.sync skeleton: design notes

- Inngest function `conn-sync` (packages/core/src/inngest/conn-sync.ts), trigger `conn/sync.requested` (event gains optional `trigger`).
  Config: `concurrency {key: event.data.connectionId, limit: 1}`, `retries: 4`. Core cannot import connectors, so
  the body calls an injected `runSync`; apps/web/app/api/inngest/route.ts wires `connSyncJob` from `@nichols/connectors/sync`.
  Lanes not in ENABLED_LANES are skipped (sendLaneEvent already refuses them; defence in depth).
- Failure translation: connector disposition `retry` -> Error / RetryAfterError (capped 15 min); anything else -> NonRetriableError.
- Job (packages/connectors/src/sync/job.ts): load connection via lane-bound loader -> skip if not active/degraded -> start run row ->
  provider runner -> finish row (succeeded|failed + redacted ConnectorErrorInfo) -> connections.last_sync_at / last_error.
  Each attempt is one sync_runs row. One connection failing returns only its own failed outcome.
- Runs: `sync_runs` via service_role table grants (no new function). New partial unique index `sync_runs_one_running_idx` (one
  running per connection, backstop). Start first cancels rows left open by the same Inngest run id (earlier attempt) or older
  than 30 min (crashed worker), so the index never blocks for good.
- Cursors: generic `Connector.sync` providers use stream `default` via new `core.sync_cursor_put` (compare-and-swap, definer,
  service_role only, lane-checked, usable connections). Cursor is written only after the connector resolved. Google mail/calendar
  keep their atomic per-page cursors; the Google runner runs mail then calendar, always both, rethrows the first failure.
- Wiring: only `google` has a runner. Other providers fail runs with unsupported_op until their sync lands (T-051 etc.).
- SQL: db-engineer subagent was not available in this session (no subagent tool); migration 20261105160000 + pgTAP 180 written
  directly and kept minimal. test:db green. 080_connections.test.sql fixture adjusted (APK run inserted as finished) because the new index
  fires before the FK check in the "another lane's connection" case.
- Not done (out of scope): scheduler/cron fan-out that sends the events; token health (T-040); object_types column (T-053);
  status -> reconnect_required on failure (T-195/T-040).
