## Decisions
1. No SQL. Everything reads existing granted columns (`core.connections.features`, `core.sync_runs.job/finished_at/status`) and the approvals module's own readers.
2. Status "disconnected": a disconnected row is not drawn as a connection (as before); when no live connection exists but one was disconnected, the not-connected row says "Disconnected" and offers Connect (view flag `wasDisconnected`). Connection rows still carry the four live states.
3. Realm id: only the last four characters reach the page ("Company ID ending 0001"). The full id is never sent to the browser (the Approvals card still shows it, T-195, a separate page).
4. Last sync: one line per job (Books = sync, Reports, Finance data = normalize), each the last successful `core.sync_runs` run; the books line falls back to `connections.last_sync_at`. Three small reads per connection (limit 1 each), RLS-guarded. A failure of those reads is `unavailable`.
5. Class tracking: from `connections.features.class_tracking`; "on", "off" (+ unsplit warning) or "not checked yet" when never detected.
6. Disconnect gate: proposing does not depend on the gate (SQL checks role, realm, one pending), so the button stays available even when `qbo_disconnect` / `approvals_live` is off. The confirm dialog and the pending line show the capability message ("approval not set up") so nobody waits for nothing. Pending proposals come from `listApprovals` (RLS), matched by connection id; a failed read hides only the pending state (the database still refuses a second one).
7. Confirm is an inline panel (role=dialog, non-modal), not a modal library; there is none in @nichols/ui. The button only asks; approval with step-up stays on the Approvals page.
8. Shared banner: `ErrorBanner` already existed in @nichols/ui (T-197 listed as its user). `quickbooks-error-banner.tsx` wraps it with fixed text for reconnect_required, degraded, unavailable and the mailto `it@pub-k.org`. The Finance page (T-084/T-092) can import it.
9. Export: client component with two date inputs (default last 30 ET days, computed on the server so there is no hydration drift) and plain `<a download>` links to T-196's route (GET, same-origin). Client-side range check (<= 90 days, matches EXPORT_MAX_DAYS, test pins it). The URL helper moved to `lib/connector-error-export-url.ts` (re-exported from the old file) so the client bundle does not pull the server handler.
10. `lane_config.pilot.connection_test_enabled` key: NOT removed from the schema. Saurabh's local DB may hold a stored config with it (set by `qbo-sandbox-dev.mjs --enable-connection-test`) and the schema is strict, so deleting the key could make that config unparsable. Only its comment was updated, and the script flag was removed. Follow-up: drop the key when no stored version has it.
11. Roles: role gating is unchanged and enforced by the loader (`requireRole` owner/admin_technical at AAL2 -> null = nothing drawn) and by every route (start 403/404, check 403/404, approvals propose 403/404, export 403/404), all tested earlier (T-050, T-195, T-196, T-198).
