# T-062 notes (mail/calendar/docs provider interfaces + mocks)

## Plan / design
- New subpath `@nichols/connectors/comms` (src/comms): Zod schemas, `UntrustedBody`, `MailProvider` / `CalendarProvider` / `DocumentProvider`.
- Providers sit beside `Connector` (connect/health/disconnect stay there). No `execute*`; `COMMS_PROVIDER_KEYS` is the closed member list and `FORBIDDEN_EXECUTE_PATTERN` backs the "no execute path" test. Writes: `prepareWrite` -> `ProposedPayload` only; execution = `ConnectorWriter` (T-063/T-116).
- Metadata records map 1:1 to T-061 `comms.message_index` / `cal.event_index` columns (no identity columns, no classifier/summary columns). `deleted` is modelled as `removals`, not a field. Event schema repeats the table check constraints.
- Sync: `sync(laneId, conn, cursor|null, {pageSize}) -> {upserts, removals, nextCursor, hasMore, fullResyncRequired}`; cursor per connection, opaque. fullResync => empty arrays + null cursor (refine enforces). Calendar provider expands recurring instances; cancelled = upsert stub (no times), hard delete = removal.
- Content: `readBody` returns `SourceResult<UntrustedBody>` (live). `UntrustedBody` keeps text in a `#private` field; JSON/inspect/spread/toString show a placeholder; `trust: "untrusted"`. Calendar `readBody(calendarId, eventId)` = description; documents search returns `DocumentLink` (url+metadata) only.
- Watch: `WatchInfo.mode` push|polling; polling has null channel/expiry. Callback URL is server config, not a parameter.
- No lane_config field (removed in review); no SQL change.
- Testing: `createMockComms` (deterministic, synthetic), `describeCommsContract` (provider/harness shape; real providers pass their MSW-backed harness). 103 contract tests across google/microsoft x push/polling.

## Review points to look at
- All-day events: the table requires start_at/end_at for non-cancelled events, so real providers must supply local-midnight instants plus exclusive dates (found when the mock fixture failed the schema).
- Documents have no sync/watch (no index table; T-186/T-187 are live search only). Say so if the acceptance "metadata sync" was meant for documents too.
- watch/renew/stop create a provider-side push channel (same class as `Connector.subscribe`); not user data. Flag if the reviewer treats it as rule 5.
- `prepareWrite` checks fromMailbox == connection mailbox (forbidden otherwise); the lane's `approvals.allowed_mailboxes` is enforced by approvals, not here. Idempotency header `X-Portal-Action-Id` is the executor's job.
- Contract per-connection-cursor check is deliberately lenient (a foreign cursor must resync or report); real providers' cursors are opaque tokens.
- Suite `checkGuards` accepts any ConnectorError for a foreign-provider connection (kind not fixed).
