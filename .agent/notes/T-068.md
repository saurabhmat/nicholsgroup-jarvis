# T-068 + T-264 plan (Microsoft change notifications, renewal and lifecycle)

Built together in one pass on `agent/T-068` (on top of the unpushed T-262/T-263 work).

Design (decisions made before writing code)
- Subscriptions are created, renewed and stopped only by the T-040 `conn.subscriptions_renew` scan (every 12 h): one `ensure(lane, connection)` per usable Microsoft connection. No other shape.
- Own client with its own allow-list (`POST /subscriptions`, `PATCH|DELETE /subscriptions/{id}`), own allowed keys per route; the four-template mail write client is untouched.
- `core.push_subscriptions` + seven definer functions (migration 20261128100000, part 31). clientState = Vault secret per subscription, never a column.
- Receiver: a dedicated handler (`webhooks/microsoft.ts`) beside the T-036 pipeline; reuses body reader, content-type check, constant-time compare, `core.webhook_events` dedupe, Inngest hand-off. Lane comes from the stored subscription row.
- Dedupe key = (lane, subscription, kind, 10 s slot): Graph has no event id and replays identical bytes.
- Debounced sync: `microsoft-webhook-sync` (batch 10 s per connection) -> one `conn.sync` per stream.
- Lifecycle: reauthorizationRequired -> mark + renew job; subscriptionRemoved -> mark removed + renew job (recreates); missed -> delta sync.
- Expiry 8,640 min (6 days, Graph max 10,080), renew window 24 h (two scans).
- GRAPH_NOTIFICATION_URL optional; checked by `getGraphNotificationUrl` (not in the graph schema, so a typo cannot stop Microsoft connect/sync/health). Unset = nothing attempted; removing it stops what exists.
- Disconnect and paused provider: rows marked removed locally; no request to Microsoft (no token / guard refuses).
