# T-302 notes: decisions beyond the brief, and what could not be verified

## The QuickBooks request (UNVERIFIED against Intuit: only the synthetic MSW fake exists; check in the sandbox, H-035 style)
`GET /v3/company/{realm}/reports/BalanceSheet?start_date=D&end_date=D&accounting_method=Accrual|Cash` (+ the client's `minorversion`), one request per
Friday D. How `balance_sheet` is planned today (`planReports`) is `start_date`/`end_date`/`accounting_method` (+ `class` when tracked); I reuse the same
parameter names with start = end = the date, the lane's `finance.accounting_method`, and NO class filter (a bank balance is the whole account, D-18).
No `summarize_column_by`: one value column, so a row is { account cell, amount cell }. Assumed, not verified: the balance is "as of end_date" for a
one-day range, and the amount is the second cell. Nothing in the repo proves either; the live check should compare one account against QuickBooks'
register for a past Friday.

## How a row is recognised as a bank account's OWN balance (connector `quickbooks/bank-balances.ts`)
A report row is kept for account id X only when ALL hold: X is in the set passed in (the connection's bank accounts from `fin.accounts`: is_bank, active,
not deleted, minus every id the payroll classification flags); the row is a leaf `type: "Data"` row whose FIRST cell carries `id = X` (digits; no label
match; a row without an id is dropped); it has exactly two cells and the second is a plain figure; and X appears on NO other cell anywhere in the
report (not on a second Data row, not on a section Header or Summary). Consequences, by design (the brief's "store nothing rather than a possibly wrong
figure"): a parent bank account with sub-accounts is not read (its header and "Total ..." carry its id and include the children); an account that
QuickBooks omits from the report (zero balance? unknown) is not stored. In both cases the cell reads "Not available" / "Not read yet" and the total of
that column is null. If the live check shows QuickBooks puts the parent's own balance on a Data row with the parent's id AND a header/total with the
same id, relax rule 3 for that shape only after seeing the real report.

## Decisions (take them out if Saturday/Friday dispute them)
1. **Storage and retention.** `fin.bank_balances` (migration `20261208100000`): unique (connection, account, date); FK to `fin.accounts (id,
   connection_id)` and to `core.connections`. Retention 26 weeks, done by the writer (rows of the called connection older than 26 weeks). The writer
   refuses a date older than 26 weeks or in the future (New York) and an `as_of` more than 5 minutes ahead.
2. **The writer replaces a date.** `core.fin_bank_balances_put` upserts the call's accounts for that date AND deletes the date's rows of accounts not in
   the call (an account that could not be read tonight is not left with last night's figure, which a back-dated entry may have made wrong). An empty
   list is allowed and clears the date. One call = one date = one transaction: a week is never half written; any account that is not a bank account
   of the connection refuses the whole call (22023, constant message, nothing written).
3. **Which accounts are asked about.** `core.fin_bank_account_ids` (service_role only) returns the connection's active, not-deleted bank accounts
   from `fin.accounts` (a superset of "Cash by account": it includes accounts not mapped to the own entity; they are stored and never shown).
   The job also removes every id the payroll classification (configured ids, Intuit payroll subtypes, name safety net) flags: defence in depth, since
   the normalizer never stores payroll accounts in `fin.accounts`.
4. **Not gated on `excluded_entity_ids`.** The reports job withholds P&L/BalanceSheet kinds while people are on `finance.payroll.excluded_entity_ids`
   (D-27 H1: their pay would show in ordinary expense lines). Bank-account balances are the same figure the Overview shows today
   (`current_balance`), no expense line is involved, so the cash history is not withheld in that case. The security review should confirm.
5. **Job placement.** After the report loop (inside `createQboReportsJob`, same connection concurrency key, same run row). A failing date is logged
   (date and error kind only) and the loop continues; the failure joins the run's outcome (retryable wins, as for reports). A token/connection problem
   stops at once. A failure never stops the report fetches (they ran first). N requests (<= 13) + 1 database read per connection per night.
6. **Settings.** `finance.reports.cash_history` (boolean, default true) added to the lane config schema; `ReportSettings` gets `weeks` and
   `cashHistory` (required). The harness default has `cashHistory: false` so the older report tests are unchanged; the empty-config test shows it is on
   by default (4 Balance Sheet reads after the 3+ report reads).
7. **Refusals of the report as a whole (fail closed, constant messages):** end period or basis different from the request; a currency other than USD
   (a bank balance in another currency would be shown as dollars); more than 20 000 rows; nesting deeper than 10; a row of the wrong shape.
8. **`finance_cash(p_lane, p_weeks default null)`.** The brief says `finance_cash(p_lane)`; I added the optional weeks like `finance_weekly` (the page
   passes only the lane; tests pass an explicit number). Same gate, same states, same weeks helper. Extra column `reason`
   (`bank_mapping_missing` / `no_own_bank_accounts`) because "Cash by account" has the same two cases.
9. **Total and change semantics.** Per column: total is null when ANY listed account of that column has no balance (`missing` counts them). Change =
   this column minus the next older column, null when either side is null; the oldest column has no change. The total's change uses the two totals
   (null when either is null). Today's column is the stored `current_balance` of the same accounts as "Cash by account" (its total equals
   `home_finance.cash_total`; tested). Column `as_of` for a week end = the OLDEST read among the accounts (min), null when nothing is stored.
10. **Balances of a disconnected connection** are ignored (the report reads only current connections), same as the other tabs.
11. **Existing tests updated, not weakened:** the tab tests (Cash is second), `050_catalog` (three function entries), `335` (a pinned readable table:
   39+7=46 -> 40+7=47), `336` (97 -> 98 callable functions, 79 -> 80 lane functions), `339` (the list of fin writers now includes
   `fin_bank_balances_put`), the lane-config default test (`cash_history: true`) and the reports test for default settings.
12. **MSW fake:** the default BalanceSheet answer now echoes the requested start/end date in its header (as Intuit does), and an optional per-date answer
   map `balanceSheetByDate` exists for tests.
