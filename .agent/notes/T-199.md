# T-199 Settings → Connections: Google section

## Plan / what was built
- No SQL change. `authenticated` can already read `core.connections` (external_account_id, status) and
  `core.sync_cursors` (lane_id, connection_id, stream, updated_at; cursor_value is not granted) under RLS (aal2, role view
  'connections' / 'health'), and `core.lane_config_current` for owner / admin_technical. So the page reads through the
  signed-in user's own lane client (`requireRole(lane, CONNECT_ROLES)`), same as T-198.
- `apps/web/lib/google-connection.ts`: `loadGoogleSection(client, laneId)` (status mapping, mailbox vs
  `lane_config.mailboxes`, last mail / calendar sync = `sync_cursors.updated_at` for streams `mail` / `calendar`),
  `googleSectionFor(guards, laneId)` (null for any AuthError; rethrows outages).
- `apps/web/components/google-connection-section.tsx`: server component; same-origin form POST to
  `/api/connect/google/start?lane=<lane>` (the start route is POST-only, like QBO). "Connect Google" /
  "Reconnect Google" (with banner) / "Connect another Google account". No Disconnect (D-24); text on removing access at Google.
- `settings-page.tsx` renders it before the T-198 section (untouched).
- No new route or action, so no new 403/404 route tests; the section is invisible for other roles and lane 404 comes
  from `loadLane`. Role gating tested in `tests/google-connection.test.ts`.

## Limits
- "Last sync" is the cursor write time, which is set only when a page is applied (not when a run finds nothing new).
  `connections.last_sync_at` exists but is a single value for the connection, so per-stream times use cursors.
- `core.sync_cursors` is not in the generated DB types yet; a narrow local cast is used.
- Playwright does not click Connect (it would leave for Google; no MSW in the next dev server). The connector flow is
  covered by packages/connectors tests with the MSW Google mocks. The e2e checks the form action/method.
- e2e seeds synthetic rows with `docker exec psql` into the local DB container (apps/web/scripts/e2e-sql.mjs; the lint
  rule forbids child_process in e2e/). Run with `LD_LIBRARY_PATH=~/.local/share/pw-libs/root/usr/lib/x86_64-linux-gnu`.
