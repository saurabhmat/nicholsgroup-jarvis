## Part 1: AI summary, automatic and reliable (no Run button)

### Decisions
- Structured output: the installed `@anthropic-ai/sdk` 1.6.0 types `output_config.format` as `JSONOutputFormat { type: 'json_schema', schema }` (no name field); `tool_choice` is never forced. `LLMRequest.outputSchema { name, schema }` is sent as `output_config.format` (merged with `effort`), validated fail-closed in `buildParams` (name shape, object schema, never with `serverTools`). The mock reuses `buildParams`, so it validates the same way and records the schema in `calls`; new test helper `jsonResult`.
- One source of truth: the Zod schema `BriefingOutputSchema` in `apps/web/lib/briefing-output.ts`; the JSON schema is `z.toJSONSchema` of it (closed objects, six required fields). Parsing: whole text, then fenced block, then `extractJson` (first `{` to last `}`), then Zod. `checkContent` (refs, grounding) and `maskContent` run unchanged after Zod.
- Retry ONCE on a parse or Zod failure: previous assistant text + a user message listing issue paths and Zod codes (and the expected type name), no values and no new email content. Refused or truncated replies are not retried. Log line `briefing.model_output_invalid` (laneId, attempt, issues = path + code) on each failed attempt; the saved failure code stays `output_invalid`.
- Auto run: `ensureFreshBriefing` (owner + AAL2 via requireRole -> model configured -> policy -> SQL claim -> `after()`), `regenerateBriefing`, `briefingRunState` (poll). `after()` from `next/server` is supported in Next 16.4 server actions; the lane client is a bearer-token client (no cookies), the tz cookie, provider and policy are captured before `after()`. The run is `runBriefingBounded` (75 s abort guarding writes, single-flight). Home's `maxDuration = 90` covers the action plus `after()`.
- SQL (migration 20261114100000): `brief.briefing_runs` (RLS, own rows, aal2 + briefing view), `brief.briefing_claim` (internal gates), `core.briefing_claim_auto`, `core.briefing_claim_regenerate`, `core.briefing_claim_schedule` (service_role), `core.briefing_run_state`, `brief.briefing_runs_close`. Gates return `{id, gate}` and never raise, so the 10-minute lost-claim close commits. Gates: not_stale (3 h, auto only), running (2 min), cap_reached (6 per lane per New York day, all kinds), rate_limited (Regenerate 30 min), cooldown (auto, 10 min after an auto/regenerate/manual attempt). `core.briefing_save_own` skips its 2-minute cooldown only while the owner has an open claim, and both saves close the claim. `core.briefing_save` (job) closes the schedule claim.
- UI: `BriefingAuto` (client, owner only) mounts once per page load, calls `ensureFreshBriefing` only if the latest good briefing is older than 3 h (SQL decides again), shows "Updating summary…", polls every 12 s for up to 3 min, then one refresh via `requestRefresh` (waits while the reply drawer holds the gate). "Summary at 9:12 AM" (today's clock time, else date + time, viewer zone) is server rendered. The ⋯ menu has Regenerate with disabled states "Updating…", "Available at <time>", "Daily limit reached (6 a day)". Run now (button and `runBriefingNow`) removed.
- Schedule: `runScheduled` records a `schedule` claim before the run (failure to record never stops the run). The schedule stays off until H-046.

## Part 1 review fixes

### What changed
- **Schema (H1).** `packages/ai/src/anthropic.ts` `buildParams` now sends `transformJSONSchema` (SDK 1.6.0, `@anthropic-ai/sdk/lib/transform-json-schema`, importable with no new dependency) of the schema with `$schema` dropped, then converts every type array (`["string","null"]`, which Zod 4.6.7 emits for `.nullable()` and the SDK transform keeps) to `anyOf`. `BRIEFING_OUTPUT_SCHEMA` also drops `$schema`. `replies` and `more_replies` are `.default([])` in Zod (a lane with drafts off may omit them without a retry); the API schema still lists them as required (output mode). Test: the schema sent has no `$schema`, no type arrays, every object closed with `required` = all properties.
- **Lane clients (sec M1).** The brain context is now loaded BEFORE `after()` (cookies available, 1.5 s limit) with `clientFor` = a memoised `requireLane(l)` for exactly the lane asked (so the home lane gets its own client, never the current lane's). After the load window closes any further request rejects with `LaneAccessError("not_allowed")`. Tested.
- **pgTAP 306 (sec M2, L2).** A real APK row (superuser insert, APK owner membership): the PKG owner at AAL2 reads 0, the APK owner reads 1. Owner B's open claim does not let owner A skip the `briefing_save_own` cooldown (`too_soon`) and B's claim stays open.
- **No sources (code M1).** The trigger renders only when the owner has mail access (`brief.mail.access`). The action checks `briefing_coverage` for a mail stream BEFORE the claim and returns gate `no_sources` (new `BriefingGate`). Tested in the action and in home-page.
- **Time budget (code M3).** Background bound 60 s (`BACKGROUND_RUN_TIMEOUT_MS`, was 75 s); it starts at the action's start, so the brain load is inside the budget (timeout passed = 60 s minus elapsed). No retry of an unusable reply when more than 40 s of the run have elapsed (`RETRY_ONLY_BEFORE_MS`; `deps.clock` for tests); the failure is saved with the usual `output_invalid` code and `briefing.retry_skipped` is logged. Home `maxDuration` stays 90.
- **No leaked claim (code M4).** The tz cookie and sources are read before the claim. Anything that throws between the claim and `after()` calls the new `core.briefing_claim_release(p_lane, p_claim)` (owner, AAL2, own open claim only; closed as `lost`). A run that dies inside `after()` (or returns `busy`) releases it too. Tested.
- **Schedule claim idempotent (code M5).** `brief.briefing_claim` for `schedule` reuses an open or finished (not lost) schedule claim of the same lane + owner + New York day. New status `lost`: a claim closed after 10 minutes, or released, does NOT count toward the 6/day cap or `runs_today`. Bound against a crash loop: the one-running gate (2 min) and the 10-minute auto pause. pgTAP covers: reuse open, reuse finished, next day claims anew, lost not counted, release.
- **Retention (code M6).** `brief.briefing_runs_purge(p_lane, p_keep_days)` (definer, service_role; floor 1; enabled lane; by New York day) + `core.briefing_runs_purge` wrapper; `purgeBriefingRuns` in the briefing jobs; registered as `brief.briefing_runs` (30 days) in `apps/web/app/api/inngest/route.ts`. pgTAP: floor, unknown lane, keeps 30 days, grants.
- **Menu a11y (code M2).** `BriefingAuto` is now a disclosure (button with `aria-expanded`/`aria-controls`, panel always rendered and `hidden` when closed, plain buttons). Regenerate uses `aria-disabled` and holds the reason text inside it, so it stays focusable and the reason is read. Escape closes and returns focus to the trigger; focus leaving the control closes it; trigger `size-11` on phones (`sm:size-8`); the status live region is always mounted and only its text changes. Tests: open/close, Escape + focus return, focus-out, aria-disabled reason, same live-region node.
- **LOW.** L1 "Run now" wording removed from code comments, test titles, the backlog H-046 text ("reviewed two briefings"), the T-235 migration comment (older, already-applied migrations keep their history; the `too_soon` mapping in `saveOwnBriefing` stays: it is reachable when a save has no open claim). L3 unknown gate -> `not_stale` (a no-op on the card). L4 `core.briefing_run_state` is `volatile`. L5 the zone abbreviation is in the `title` of "Summary at" ("Times in EST"). Sec L1: run state and cap are lane-wide by design (one cost cap per lane; documented in the migration and the action). Sec L4: per-tab sessionStorage guard (`briefing-ensure:<lane>`, 10 min) so a remount does not call `ensureFreshBriefing` again.
